## 2 调研抄法摘要

### §2.10 telemetry（失败归因遥测）
- autoflow：在返回 dict 上挂 `_telemetry`（零侵入，不改控制流）；归因走**规则**而非 LLM（离线可用、可测）。
- **兜底方向**：宁可多归「网关/上游」，**不冤枉 agent**——归因错怪 agent 会误导修法。
- **抄法**：`af_telemetry.attach(result, ...)` 统一在服务层出口调用；append-only JSONL 便于事后分析。

### §2.11 error_knowledge（错误知识库）
- autoflow：**有序正则表**（顺序 = 优先级，首个命中即返回）；每个类别有**专门建议**（不落 `other`）；存储有界。
- **抄法**：`RULES: tuple[(Pattern, category)]`；`classify()` 首个命中；`CATEGORY_ADVICE[category]` 必非空。

### §2.12 experience（经验/共现）
- autoflow：实体共现 **无向去序**（`sorted([a,b]) → "a|b"`），避免 `a|b`/`b|a` 分裂；**只在成功时更新**（失败样本不污染）。
- **抄法**：`ExperienceStore.observe(graph, ok=True)` 仅在 `ok` 时累加；`export()` 出结构化 JSON 供 MA 消费。

### §2.16 token 统计
- autoflow：按字符数 `/4` 估算（无 tokenizer 依赖），四维聚合（tool / 方向 / 结果 / 日），保留 30 天。
- **抄法**：`estimate_tokens(*texts) = ceil(chars/4)`；`usage_summary(days=30)`。

### C §3 P2 解析遥测 + 自然语言消歧
- 五档计数落 `{root}/.catalog/resolve_metrics.json` → 真实**成功率漏斗**；
- 歧义时**复用** `Diagnostic.hint` 出口给消歧提示（如「书房电脑 是 switch 开机卡，不是 light」），**不另造机制**。

## 4 行为增量（逐交付点）

### 4.1 错误知识库（`af_error_knowledge.py`）

```python
CATEGORY_ADVICE: dict[str, str]  # category → 必非空的「怎么修」
RULES: tuple[tuple[re.Pattern[str], str], ...]  # 有序：顺序即优先级

def classify(message: str) -> str        # 首个命中；无命中 → "UNKNOWN"
def explain(message: str) -> dict        # {"category","label","advice","matched"}
class ErrorKnowledge:
    def __init__(self, root: str | Path, *, max_records: int = 500) -> None: ...
    def record(self, message: str, *, category: str | None = None, context: dict | None = None) -> dict
    def recent(self, *, limit: int = 20) -> list[dict]
    def similar(self, message: str, *, limit: int = 3) -> list[dict]   # 同类历史
    def counts(self) -> dict[str, int]
    def prune(self) -> int
```

**类别集**（初版，覆盖现有诊断/异常码；精确类别**必有专门建议**）：
`IR_SCHEMA`（Schema/必填）、`IR_SEMANTIC`（静态扫描 error）、`ENTITY_NOT_FOUND`、`ENTITY_GUARD_TIER0`、`L3_ACTION`、`LOW_CONFIDENCE`、`SCOPE_DENIED`、`PENDING_LIMIT`、`BLAST_RADIUS`、`OWNERSHIP`、`WRITE_CONFLICT`、`TOKEN_EXPIRED`、`UPSTREAM_HA`、`GATEWAY_HTTP`、`HTTP_NOT_WHITELISTED`、`UNKNOWN`。

**兜底方向**：无法归因时 → `UNKNOWN` + 通用建议；**优先**把「上游/网关/网络」类线索归到 `UPSTREAM_HA`/`GATEWAY_HTTP`，避免误判成 agent 写错 IR。

**存储**：`{root}/error_knowledge.jsonl`（append-only），读取时有界（最近 `max_records`）；`record` 后超限 `prune`。

### 4.2 遥测（`af_telemetry.py`）

```python
def estimate_tokens(*texts: str) -> int          # ceil(chars/4)
def attach(result: dict, *, tool: str, root, ok: bool | None = None,
           message: str = "", context: dict | None = None) -> dict
    # 就地补 result["_telemetry"] = {"ok","category","label","advice","tokens","ts","history"}
def record_failure(root, *, tool: str, message: str, context=None) -> dict
class TelemetryStore:
    def __init__(self, root, *, retention_days: int = 30) -> None: ...
    def record(self, event: dict) -> None
    def usage(self, *, days: int = 30) -> dict   # 四维聚合：tool / dim / ok / day
```

- `_telemetry` 形状：`{"ok": bool, "category": str, "label": str, "advice": str, "tokens": int, "ts": iso, "history": [同类历史…]}`；非失败时 `category=""`、`history=[]`。
- **零侵入**：`attach()` 只补一个下划线键，绝不改 `ok`/`errors` 等既有字段，也不改控制流。
- 存储 `{root}/telemetry/usage.jsonl`，`usage()` 按 `retention_days` 截断。

### 4.3 经验/共现（`af_experience.py`）

```python
class ExperienceStore:
    def __init__(self, root: str | Path) -> None: ...
    def observe(self, graph, *, ok: bool = True) -> dict   # ok=False 直接返回，不污染
    def top_pairs(self, *, limit: int = 20) -> list[dict]  # {"pair":"a|b","count":n}
    def top_entities(self, *, limit: int = 20) -> list[dict]
    def patterns(self) -> dict                             # 节点 kind 序列 / mode / adapter 计数
    def export(self) -> dict                               # 供 MA：{"pairs":[...],"entities":[...],"patterns":{...},"generated_at"}
    def clear(self) -> None
```

- **无向去序**：`pair = "|".join(sorted({a, b}))` → `a|b` 与 `b|a` 合并；同实体不配对。
- **只在成功时更新**：`observe(graph, ok=True)`；失败样本完全不进。
- 存储：`{root}/experience.json`（原子写），`export()` 供 `af_metrics` 之外的 MA 消费面（双向：AF 采集事实 → MA 生成假设）。

### 4.4 失败回执附历史同类（写→读闭环）

- `af_service.build()` → `ok:false` 时 `_telemetry.category = classify(首错message)`、`advice`、`history = ErrorKnowledge.similar(首错message)`。
- `af_mcp.dispatch()` 异常路径 → `record_failure(...)`（落知识库），并在 `ServiceError` 文本后追加 `（归因：<label>；建议：<advice>）`。
- `forge sim` 失败（IR 非法 / expect 不满足）→ CLI 打印归因 + 历史同类 3 条。

### 4.5 token 统计（`af_telemetry.TelemetryStore.usage`）

四维：`by_tool` / `by_category` / `by_ok` / `by_day`；`estimate_tokens` 用于每条 `_telemetry`。

### 4.6 实体共现 → 喂 MA

`ExperienceStore.export()` 结构化输出；`GET /api/experience?format=export` 与 `af_experience` MCP 工具暴露；MA 消费面文档补 `docs/MA_METRICS_CONTRACT.md` 一节。

### 4.7 解析遥测五档（`af_catalog.resolve`）

- `resolve()` 汇总出口计**五档**并累加 `{root}/.catalog/resolve_metrics.json`（原子写）：
  - `exact`：`entity_id_exact` / `friendly_name_exact` 且唯一或 top 明确；
  - `medium`：`friendly_name_substr`；
  - `low`：`entity_id_substr`；
  - `ambiguous`：多候选且 top confidence ≤ medium（无法唯一裁决）；
  - `none`：0 候选。
- 返回附加 `bucket` 字段（**附加，不破坏既有结构**）；`resolve_metrics()` 读出漏斗 `{exact,medium,low,ambiguous,none,total,success_rate}`。

### 4.8 自然语言消歧（复用 `Diagnostic.hint`）

- `resolve()` 歧义时返回 `disambiguation`：`{"hint": str, "candidates": [{"entity_id","domain","friendly_name","why"}]}`；
- `hint` 文案复用**域契约**（`af_affordance`）与 v1.2.0 的 `Diagnostic.hint` 出口语义：如
  `「书房电脑」是 switch 开机卡（可取值 on/off），不是 light（on/off）——请用 entity_id 明确指定，或加 --domain 收窄`。

## 5 关键约束落实（逐项对照 ROADMAP 约束）

1. **归因纯规则、零 LLM** → `af_error_knowledge.RULES` 全为 `re.Pattern`，无网络调用。
2. **精确类别必须有专门建议** → 单测断言 `all(CATEGORY_ADVICE[c] for c in _KNOWN_CATEGORIES)`；`classify` 不返回空。
3. **共现采集挂钩写操作成功态** → `observe(graph, ok=...)`，`af_service.save_graph`/`approve_pending` 成功路径调用。
4. **所有存储有界（500 条 / 30 天）+ 原子写** → `ErrorKnowledge(max_records=500)`、`TelemetryStore(retention_days=30)`、`ExperienceStore` 原子写（`.tmp` → `os.replace`）。
5. **`_telemetry` 零侵入** → 只新增下划线键；既有键与语义不变（回归保护）。

## 7 风险与开放问题

1. **`simulate` 恒 `ok:True`**：失败以**异常**形式抛出（`IRValidationError`）。故 `_telemetry` 在 `simulate` 上主要承载 token 估算；归因落在**异常回执**（MCP/CLI/HTTP 边界）与 `build` 的 `ok:false`。
2. **常驻进程才有真实 runs**：`get_metrics` 的 runs/success 仅 `forge serve/watch` 进程内有效（既有事实）；本版遥测同理——CLI 一次性调用只落单条事件。文档需注明。
3. **`{root}/.catalog/` 写入并发**：`resolve_metrics.json` 读改写用 `FileLock`（复用 `af_flock`），避免多进程丢计数。
4. **共现样本量**：小规模（几十对）无需上界；若后续膨胀再加 `top_n` 截断（本版已给 `limit` 参数）。
5. **归因兜底口径**：宁可归上游（`UPSTREAM_HA`/`GATEWAY_HTTP`）不冤枉 agent——已在 `RULES` 顺序中体现（网络/超时/5xx 规则置于 IR 语义规则**之前**）。
