# AutoForge 与 Home Assistant 的语义差异

> 版本：v1.0　日期：2026-09-14
> 关联：`IR_AND_RUNTIME.md` v0.2.1｜`KICKOFF.md` §4.3、§4.6、§5.1

> **为什么要有这份文档**：AutoForge 大量复用 HA 的概念（mode、`for:`、太阳历），但有几处**有意偏离**。
> 若不在文档中固化，仿真与真机会出现"看起来一样、跑起来不一样"的漂移——这正是 AutoFlow v1 的主要缺陷来源之一。
> **所有偏离点必须在 NL 渲染文本中可见**（让用户读到的那句话与真正跑的逻辑一致）。

---

## 1. 有意偏离（AutoForge ≠ HA）

| # | 主题 | HA 行为 | AutoForge 行为 | 理由 | NL 渲染要求 |
|---|---|---|---|---|---|
| 1 | **`restart` 模式** | 终止旧实例重建，**不执行任何清理动作** | **触发旧实例的 `on_cancel` 分支**后再 spawn 新实例 | `on_cancel` 本就是清理钩子；不触发则清理逻辑形同虚设 | 渲染文本须写明"重新触发时会先执行取消后的清理动作" |
| 2 | **`on_error` 边** | HA 无对应概念（异常即终止并写日志） | 第 6 种边，可被显式捕获并指定后续节点 | 中断/超时/失败三类语义解耦；扫描器可精准强制 | 须渲染"如果执行失败，则…"分支 |
| 3 | **快照边界** | 模板渲染时每次取实时状态 | 求值段内用**原子快照**；`do` 的结果只写 `vars`，**不回写快照** | 禁止"开空调后立刻判断温度是否变化"这类反直觉时序 | 须体现"本段判断基于触发瞬间的状态" |
| 4 | **`ask` 会话维度** | HA 无原生"询问并等待人类应答"节点 | 强制绑定会话维度（默认 `room`），同维度多实例按**创建时间优先**匹配，未匹配走 `default`，一次应答仅生效一次 | 家庭里多房间并发询问必须消歧义 | 须写明"在哪个房间应答就生效" |
| 5 | **实体漂移** | 模板引用不存在实体 → 报错/静默失败 | 走 `on_error` **软失效** + 漂移告警，**不直接 failed** | 实体 ID 会随集成重登漂移（AutoFlow v1 血泪） | 告警须出现在审计报告 |
| 6 | **实体变更熔断** | 无（依赖用户自己避免循环） | 单实体 10s 内变更 ≥5 次 → 熔断该实体所有触发分发，30s 后恢复 + 审计 | 隐式循环（A 开灯→B 关灯→A）在静态图上看不出来 | 熔断事件进审计，不影响 NL 文本 |
| 7 | **适配器超时** | 集成内部自带重试/超时 | 适配器**只做单次下发**；语义层重试/降级必须由 IR 显式表达；**仅保留传输层** connect/socket 超时 | 适配器自带隐式逻辑会让 Graph 不再是唯一真相 | 无（属实现约束） |
| 8 | **并发配额** | 单条自动化按 mode 控制，无全局配额 | 全局并发默认 100、单条默认 10，`queued` 队列上限 10，超限拒绝 + 审计 | 防止 Agent 批量产出自动化打崩 Runtime | 无 |

## 2. 刻意保持一致（与 HA 对齐，勿擅自改动）

| 主题 | 对齐点 |
|---|---|
| **并发 mode** | `single` / `restart` / `queued` / `parallel` 语义与 HA 一致（除上表 #1） |
| **`for` 语义** | **边沿触发 + 持续时长**：状态跃变后需持续满足时长才触发，**不是电平触发**。条件破坏即取消（验收用例 2） |
| **事件时间戳** | 一律取 HA 的 `last_changed`，**不取本地 `datetime.now()`** |
| **太阳历 / 日历** | vhass 基于 `pytest-homeassistant`，`sun.below_horizon` 等为 HA 原生实现（验收用例 3） |
| **状态字符串** | `on`/`off`/`home`/`not_home` 等沿用 HA 字面量 |

> ⚠️ `for` 是否需支持真正的"电平触发"仍是未决事项（`IR_AND_RUNTIME.md` §18-2）。**G1 一律按边沿+持续实现**，不要凭直觉加电平分支。

---

## 3. 取消语义（不回滚）

`on_cancel` 命中后：**仅停止流转，不回滚已执行的动作**（开灯后被取消，灯保持亮）。
清理动作必须**显式写在 `on_cancel` 分支**里。

理由：家庭物理世界不可逆，强行回滚极易反直觉（用户已经看到灯亮了，再自动关掉更困惑）。
对应验收用例 5。

## 4. 新增偏离的流程

1. 在本文档第 1 节追加一行，写清「HA 行为 / AutoForge 行为 / 理由 / NL 渲染要求」；
2. 同步更新 `IR_AND_RUNTIME.md` 对应章节；
3. 在 `tests/acceptance/` 增加一条能观测该差异的用例；
4. 若影响 NL 文本，`af_nl.py` 必须同步修改，否则违反「看到即跑的」铁律。
