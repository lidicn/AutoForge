## 2. 行为增量

- **新增能力**：
  - `forge run --live`：真实下发到 HA（`POST /api/services/{domain}/{service}`），状态读 HA REST（`GET /api/states`）。
  - 真机 Runtime 装配：`HAAdapter(transport=HATransport(...), dry_run=False)` → **canary 灰度保护真正生效**（G4 已知 dry-run 跳过 canary）。
  - 四道真机闸（`live_preflight`）：缺令牌 / 缺二次确认 / 缺白名单 / 写目标越界，任一不满足即拒绝下发。
- **对外契约（CLI）**：
  - `run --live --confirm --ha-token <t> --entities <清单> [--live-allow <可写子集>] [--ha-url <url>]`
  - `--live-allow`：真机可写实体白名单（逗号分隔）；缺省复用 `--entities`。用于"有完整实体清单，但真机只放行其中几个"。
  - `--live` 只对 `run` 生效；`sim` 上会被忽略并提示。
  - 令牌亦可经环境变量 `AUTOFORGE_HA_TOKEN` 提供。
- **无 IR Schema 改动**；`--entities` 语义不变（存在性校验清单）。

## 4. 已知风险 / 残留项

- [ ] `live_preflight` 的"写目标越界"（`LIVE_ENTITY_NOT_WHITELISTED`）与静态闸 `ENTITY_NOT_FOUND` 有**部分重叠**：当 `--entities` 给全时，写目标不在其中会先被 `ENTITY_NOT_FOUND` 拦。`--live-allow` 提供了**更窄**的真机可写子集，使越界检查真正独立可触发（见测试）。不影响主链路。
- [ ] `forge run --live` 目前**无事件则不下发**（CLI 是回放式，一次性执行后退出）；真机常驻监听（订阅 HA 事件流）不在本轮范围，属后续"常驻 Runtime"话题。
- [ ] `HAStateProvider` 每次 `snapshot` 拉全量 `/api/states`；实体多时可按需改为按实体拉取（当前实现简单优先）。
- [ ] 真机写设备为**高风险操作**：务必先用 `--live-allow` 收窄到单个实体验证。
