## 1. 配对码（MCP 连接认证）

**配对流程（已确认）**：agent 发起 MCP 连接请求 → 后端生成 6 位配对码 → 通过 SSE 推送到 ForgeSight 前端弹窗显示 → 用户在聊天里把码告诉 agent → agent 拿码调 `af_pair(code)` 兑换 MCP token → 配对完成。

**重要**：ForgeSight 上**没有"生成配对码"按钮**。配对码由 agent 请求连接时后端自动生成。

需确认：

- [ ] `af_pair(code)` MCP 方法当前是否已实现？在哪个 MCP server / 端口？
- [ ] SSE 端点 `GET /api/mcp/pair-request`：agent 发起连接请求时，后端推送 `{agent_name_hint, code, expires_at}` 到前端。这个 SSE 端点是否能实现？
- [ ] 配对码是否单次性？时效多久？（前端只展示，不设定时长）
- [ ] 配对码绑定到具体用户？（多用户场景）
- [ ] **agent 初始名称**：agent 配对时通过 MCP 传递 `agent_name` / `client_name` —— 当前是否已实现？如未实现，请在 `af_pair` 入参中增加该字段，否则 UI 上连入的 agent 只能显示"未命名Agent1/2…"。

## 2. 授权码（部署授权）— 与配对码是两个东西

授权码用途：agent 写好自动化后**部署到 AF** 时携带。有有效授权码 → 路径 A 直接部署；无授权码 → 路径 B 入 Pending 等用户手动批准。

需后端新增：

- [ ] `POST /api/user/auth-code`：生成授权码
  - 入参：`{ttl: 'short'|'long', duration_minutes?: number}`（短期时用户选 5/10/自定义分钟数；长期无过期）
  - 出参：`{code, expires_at}`（长期码 `expires_at=null`）
  - 长期码为 6 位数字，不撤销一直可用
- [ ] agent 部署自动化时携带授权码：后端校验有效性 → 有效则直接部署，无效/缺失则入 Pending
- [ ] `DELETE /api/user/auth-code/{code}`：撤销长期授权码
- [ ] `GET /api/user/auth-codes`：列出当前用户已发出的授权码（含已用/未用状态），供 UI 设置区展示和撤销
