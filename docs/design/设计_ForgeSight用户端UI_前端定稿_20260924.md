## 1. 产品定位

ForgeSight 是 AutoForge 面向**家庭用户**的移动端 WebUI（PWA）。用户在这里：

- 管理已连入的 agent（查看、删除配对）
- 查看和管理自动化（启用/禁用/归档/删除）
- 批准待审批的自动化
- 生成授权码给 agent（让 agent 可以直接部署自动化）
- 查看试演期状态

**铁律**：不展示 IR、Graph、SpecEditor、治理后台、日志等引擎内部细节。只展示结论性信息。

## 3. Tab 1：Agent（已连接的 agent）

### 3.1 列表

显示所有已连入 AF 的 agent：

| 字段 | 说明 |
|---|---|
| 名称 | agent 名称；连入时未传名称则兜底显示 `未命名Agent1`、`未命名Agent2`…；点击名称可内联改名 |
| 最后连入时间 | 最近一次活跃时间 |
| [删除配对] | 点击后吊销该 agent 的 MCP token 并从列表移除（二次确认） |

> Agent Tab 只做**连接管理**，不嵌套自动化列表。自动化全部归「自动化 Tab」，按 agent 名称分组展示（见 §4.2）。

### 3.2 新 agent 连接弹窗

当有新 agent 通过 MCP 发起连接请求时，屏幕中间弹出配对确认弹窗：

```
┌──────────────────────────┐
│                          │
│   workbuddy 请求 MCP 配对  │
│                          │
│   配对码：1 7 0 8 4 6    │
│                          │
│   （6 位数字，用户转告 agent）│
│                          │
└──────────────────────────┘
```

**流程**：agent 发起 MCP 连接 → AF 生成配对码 → ForgeSight 弹窗显示 → 用户在聊天里把配对码告诉 agent → agent 用配对码兑换 token → 配对完成，agent 出现在列表中。

**注意**：
- ForgeSight 上**没有"生成配对码"按钮**。配对码由 agent 请求连接时自动生成并弹窗展示。
- 配对码时效短（具体时长后端定，前端只展示）。
- agent 名称在配对时通过 MCP 传入（后端当前可能未实现，见咨询单）。

**前端实现**：App 启动后建立 SSE 长连接 `GET /api/mcp/pair-request`（见 §9.2），收到配对请求事件即弹窗。弹窗带配对码倒计时，超时自动关闭。

## 4. Tab 2：自动化

### 4.1 顶部子标签

左侧两个子 Tab：

- **启用**：所有处于启用/待批状态的自动化
- **归档**：已归档的自动化（软藏，可恢复）

### 4.2 自动化卡片列表

列表**按 agent 名称分组**（折叠分组头），无 agent 归属的归入「未归属/本地」。分组头显示 agent 名称 + 该组自动化数量。

每条自动化一张卡片：

```
┌──────────────────────────────────┐
│  入户场景自动化          [待批]  │
│                                  │
│  开门后自动开灯并打开空调          │
│  —— 预演效果（中文一句话）        │
│                                  │
│  涉及设备：客厅主灯 · 书房空调     │
│                                  │
│  最近触发：2小时前 · 近7天 3次    │
│                                  │
│  [批准] [驳回]        [禁用] [归档]│
└──────────────────────────────────┘
```

**卡片字段**：

| 字段 | 说明 |
|---|---|
| 名称 | 自动化名称 |
| 状态标签 | `待批` / `启用` / `禁用` / `异常暂停` |
| 预演效果 | 中文一句话描述（后端 `preview_nl`）；保真度不足时前缀"仿真估算" |
| 涉及设备 | `friendly_name` 标签列表，点开弹窗显示 `friendly_name + entity_id`（后续再加设备实时状态） |
| 最近触发 | `last_triggered` + 近 7 天次数 `trigger_7d` |
| 试演期状态 | 卡片上显示当前处于 `auto / shadow / canary`；异常时变红并显示原因 |

**操作按钮**：

| 按钮 | 状态条件 | 行为 |
|---|---|---|
| [批准] | 状态=待批 | 批准后自动化生效，进入试演期 |
| [驳回] | 状态=待批 | 弹窗填理由，确认后移除 |
| [禁用] | 状态=启用 | 切换为禁用，apply 时跳过 |
| [启用] | 状态=禁用 | 恢复启用 |
| [归档] | 任意活跃状态 | 软藏，移到"归档"子标签 |
| [恢复] | 状态=归档 | 从归档恢复到启用列表 |
| [删除] | 任意 | 硬删（二次确认） |

### 4.3 待批项的展示

待批自动化**不单独开 Tab**，直接混在"启用"子标签列表最上方，带 `[待批]` 标签和 [批准]/[驳回] 按钮。用户打开自动化 Tab 就能看到。

## 5. Tab 3：授权码

### 5.1 两种授权码

| 类型 | 说明 |
|---|---|
| **长期授权码** | 6 位数字，不撤销一直可用。生成后长期有效。 |
| **短期授权码** | 用户通过滑块设定时长，最低 5 分钟，最高 30 分钟。到期自动失效。 |

### 5.2 界面

```
┌──────────────────────────────────┐
│  长期授权码                       │
│  ┌────────────────────────────┐  │
│  │ 4 8 2 9 1 7        [删除] │  │
│  │ 生成于 2026-09-24          │  │
│  └────────────────────────────┘  │
│                                  │
│  [生成长期授权码]                 │
│                                  │
│  ─────────────────────────       │
│                                  │
│  短期授权码                       │
│  时长：────●────── 15 分钟       │
│  [生成短期授权码]                 │
│                                  │
│  ┌────────────────────────────┐  │
│  │ 7 3 0 5 2 1   12分钟后失效 │  │
│  └────────────────────────────┘  │
└──────────────────────────────────┘
```

**交互**：
- 生成授权码后，码以大字号展示，方便用户转告 agent
- 每个码右侧有 [删除] 按钮（撤销）
- 短期码显示倒计时/剩余时间
- 长期码显示生成时间

### 5.3 授权码用途

agent 写好自动化后部署时：
- **有有效授权码** → 直接部署（路径 A），自动化立即生效并进试演期
- **无授权码** → 自动化进待批队列，用户在自动化 Tab 手动批准（路径 B）

## 6. 登录（v1 单 owner：无登录页）

> **v1.9.0 决策回退**：v1 为单 owner，无登录页、无用户表。App 启动直接进入主界面（默认 Agent Tab），
> 令牌由已下发的配置经 `localStorage` 持久化（参考 `ui/` 的 Bearer 做法），无登录流程。
> agent 与自动化归单一 owner；「跳转开发面板」对 owner 恒显（见 §7）。

## 7. 设置（右上角齿轮图标）

点击右上角齿轮弹出设置面板（抽屉或弹窗）：

| 选项 | 说明 |
|---|---|
| 给 agent 改名 | 内联编辑（与 Agent Tab 列表同源） |
| 跳转开发面板 | 链接到 `ui/` 开发控制台（**v1 对 owner 恒显**，不再按角色隐藏） |
| 长期授权码管理 | 查看/撤销（也可在授权码 Tab 直接操作） |

## 8. 试演期状态展示

自动化卡片上展示试演期信息：

- 当前阶段：`auto`（正式运行）/ `shadow`（影子模式，只观察不执行）/ `canary`（灰度）
- 进入试演期的时间
- **异常状态**：如果冲突仲裁器/断路器检测到异常，卡片变红，显示异常原因，标注"已自动暂停"
- 用户看到异常后可以选择：[恢复运行] 或 [回退/删除]

前端只展示状态，不自动恢复。

## 10. 技术栈

- Vue 3.5 + Vite 6 + TypeScript + Pinia 3 + Vue Router 4 + Naive UI 2.45
- `@vueuse/core`：手机端工具（在线状态、页面可见性、防抖等）
- PWA：`vite-plugin-pwa`（manifest 可安装，离线 SW 谨慎开启）
- Mobile-first 响应式
- API-first：`src/api/client.ts`（真端点）+ `src/api/mock.ts`（桩数据），`VITE_USE_MOCK` 切换
- 目录：`ui-user/src/{api, components, router, types, views, stores}`
- 不引入动画库（Vue `<Transition>` + CSS 足够）；不引入图表库

## 12. 动画方案

原则：动画只在"状态变化"和"需要用户注意"时出现，不做装饰性动画。

| 位置 | 动画 | 时长 |
|---|---|---|
| 配对码弹窗 | scale 0.9→1 + fade in；6 位数字逐位翻转入场 | 300ms + 每字 80ms |
| 配对码弹窗 | 边框 subtle pulse 呼吸光晕 | 2s 循环 |
| Tab 切换 | 内容区 fade + 轻微左右滑 | 150ms |
| 卡片状态变化（待批→启用） | 标签颜色渐变 + 顶部绿色高光闪过 | 400ms |
| 异常暂停 | 卡片变红 + 边框快速 pulse | 1.5s 循环 |
| 分组折叠/展开 | 高度过渡 | 200ms |
| 授权码生成 | 6 位数字 flip/count-up 入场 | 每字 100ms |
| 操作反馈 | toast 滑入（Naive UI `useMessage`） | 200ms |

不做：页面转场动画、背景视差、粒子效果、hover 微交互。
