## 2. 行为增量（与 v0.3.0 的差异）

- **新增能力**：一条自动化可以订阅另一条发出的自定义事件，跨自动化协作闭环打通：
  `emit` → 总线 `event.<name>` → 调度器驱动 `on event` 入口 → 订阅者实例。
- **关键设计决策**：`on event` 实现为 **`on` 节点的一种 trigger 类型**
  （`{"type": "event", "event": "<name>"}`），**不新增节点 kind**——与 v0.3.0 把 `emit` 做成"节点字段"的决策对称，
  都不触碰「7 种节点」铁律与 `IR_AND_RUNTIME.md` §5 表述。
- **匹配语义**：按总线主体 `event.<name>` **精确匹配，不支持通配符**（KICKOFF §4.1）；
  事件名不匹配即不触发（已单测锁定）。
- **事件边进依赖矩阵**：`Trigger.entity_ids()` 对 `event` 类型返回 `event.<name>`，
  因此 v0.3.0 的 `EMIT_SELF_LOOP` 环检测**自动覆盖** `emit → on event` 的间接环，无需额外代码。
- **闭环的关键修补（本次核心发现）**：
  `NodeExecutor._publish_emit()` 直接调 `bus.publish_custom()`，**绕过了 `Runtime.publish()` → `Scheduler`**，
  导致 emit 出去的事件"发了但没人接"。本次通过 `executor.on_emit` 回调（Runtime 注入 `scheduler.handle_event`）补上这一段，闭环才真正成立。
- **对外契约**：
  - IR Schema：新增 trigger 类型 `event`（向后兼容，旧图不受影响）。
  - AF-Spec：`on` 节点的 trigger 本就是内联 JSON，**自动支持**，往返无损。
  - CLI / HTTP：无新增子命令与端点。

## 4. 已知风险 / 残留项

- [ ] **伪实体 ID 进入快照预取**：`Trigger.entity_ids()` 对 `event` 返回 `event.<name>`，
  而 `Automation.reads()` 又用 `entity_ids()` 做快照预取 → 会尝试读取 `event.study_light_on` 这个"实体"
  （FakeHA 返回 `default_state_for` 的 `unknown`）。**当前无害但多余**，后续可让 `reads()` 排除 event 类型。
- [ ] **递归深度**：A→B→A 链式事件在理论上可形成调用栈（编译期有 `EMIT_SELF_LOOP`、运行期有总线熔断兜底），
  但未对"链式深度"设显式上限。
- [ ] **Web 控制台未展示事件链路**：ROADMAP v0.4.0 第 5 项（"Web 控制台展示事件链路"）**未做**，
  前端仍无 emit / on event 的可视化；`/api/sim` 的审计里能看到 `event_emitted`，可作临时观测手段。
- [ ] **事件过滤仅按事件名**：ROADMAP 原定"来源 automation / 字段匹配"的过滤**未实现**，
  当前只按事件名匹配；载荷过滤待需求驱动。
- **影响范围**：以上均为能力增强的边界说明，**不影响生产 Runtime 主链路**，也不破坏既有行为。
