## 一、单写者租约（裁定 A：抢不到锁降级只读）

- `af_cli.serve` 在 `build_app` 前用 `af_flock.FileLock.try_acquire()` 抢 `{store_root}/.serve.lock`；被占则 `readonly=True` 并打醒目日志（含持有者）。
- `af_api.build_app(readonly: bool = False)` 新增只读参数：只读时把 `_write` 依赖换成拒绝依赖（503），并对无 `_write` 守卫的建/改自动化端点（`/api/build`、`/bind`、`/sim`、`/spec/compile`）补只读守卫。
- 单测：`tests/unit/test_af_api.py` 三项（只读 503 / 非只读 ≠503 / `/api/build` 只读 503）。

## 二、WAL（裁定 B：增强现有，非 A 全量）

- `af_persist` 落盘记录加 SHA256 校验和（对齐 `af_store`），`load`/`records` 读时校验；不匹配 → 拒收/跳过 + 告警（损坏段跳过）。
- **不改存储格式头**：旧记录无 `_sha256` 字段照常加载（向后兼容，无迁移）。
- 单测：`tests/unit/test_af_persist.py` 三项（校验和往返 / 篡改拒收 / 旧格式兼容）。
