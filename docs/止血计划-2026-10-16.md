## 动作 0：修 watch 进程孤儿问题（评审指出的真根因）

**问题**：approve 后 start_watch 起的子进程，serve 进程退出时不管它，docker restart 后 watch 变孤儿占着协调锁。

**做法**：写 entrypoint.sh：
```bash
#!/bin/bash
# 起 serve
forge serve ... &
SERVE_PID=$!
# 等 serve 起来后自动起 watch（调 _build_merged_ir）
# trap 信号，退出时先杀 watch
trap 'kill $WATCH_PID 2>/dev/null; kill $SERVE_PID 2>/dev/null' TERM INT
wait
```

**注意**：改 compose 的 command，不改 Dockerfile CMD（compose 会覆盖）。

**验收**：`docker restart autoforge-api` 后，15 秒内 watch 自动起来（start_watch 探测退避表合计 11.9 秒），自动化生效。

**预估**：30 分钟

## 动作 1：修 IR 合并 bug

**三个 bug 分别修：**

### 1a. bootstrap 过滤不生效
- 现状：读 `tags`，但 record 里没有 tags 键
- 改：`note.startswith("bootstrap")`

### 1b. priority 分配逻辑
- 现状：在遍历 do 节点时反复覆盖同一个 auto 的 priority
- 改：先收集 `entity_id → [auto_id]`，再统一分配递增 priority

### 1c. Automation → dict 转换
- 现状：已确认用 `auto.raw`，raw 里 nodes/edges/meta 都在顶层
- 确认：raw 直接 append 到 all_autos 即可，不需要包一层

**验收**：approve 一条新自动化后，watch 自动重启，包含所有用户部署的自动化，不再出现 ENTITY_WRITE_CONFLICT。

**预估**：1 小时

## 动作 2：后端 hot-reload

**前提确认：**
- Dockerfile 是 `pip install -e`（editable），挂 volume 生效 ✅
- 容器以 uid 1000 非 root 跑——需确认 NAS 上 src 目录对 uid 1000 可读
- NAS 部署目录 `/vol1/1000/docker/autoforge/` 是不是 git 工作区——待确认

**做法**：compose 临时加 volume：`- /vol1/1000/docker/autoforge/src:/app/src`

**验收**：改一行 Python 代码 → git push → ssh pull → docker restart，1 分钟内生效。

**预估**：15 分钟（含前提确认）
