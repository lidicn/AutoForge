## 一、口径与射程

1. **射程**＝`src/autoforge/**/*.py`（递归，含 `af_adapters/`）。`scripts/`／`tests/` 里的日志**不在射程内**——
   它们不是常驻运行时的组成部分，门禁脚本自己写 `print` 而不是 `logger`，把它们算进来会让读数失去"这就是线上那台进程"的含义。
2. **站点判定**＝`ast.Call`，`func` 是 `ast.Attribute` 且属性名 ∈ 六级别（`debug`/`info`/`warning`/`error`/`exception`/`critical`），
   且被调对象是**logger 名**：本模块里绑定到 `logging.getLogger(…)` 的名字 ∪ 字面名 `logger`／`log`，
   或者被调对象本身就是内联的 `logging.getLogger(…)` 调用。**注释与 docstring 里出现 `logger.warning` 不算**
   （§二之九十九 同一条教训：判调用只认 `ast.Call` 节点）。
3. **具名码**＝首参里第一个非空字符串片段（`Constant` 或 f-string 的首个 `Constant`）的**首个空白分隔 token**，
   整词匹配 `^[A-Z][A-Z0-9_]{5,}$`。这是"这一条留痕有身份"的最小机器可读形状；`"CATALOG_LOAD_FAILED path=%s err=%s"`
   算命中，`"canary 心跳失败"` 不算（中文短语没有身份，不可对撞）。
4. **射程外的形状也报数**：不满足第 2 条的级别名调用（例如 `self.<某对象>.warning(…)`）不站点化，但计数行进自动段——
   现读 **0 枚**，也就是"全树只有一种 logger 获取形状"这件事今天是被机器看着的。哪天冒出第二种形状，
   这一格会变非零并逼人来决定口径要不要扩（§七 问 4），而不是让扫描器静默漏掉它。
5. **本门判的是"有没有对账"，不是"日志写得好不好"。** 存量无码站点（§四 六行合计 125 枚；⛔ 这个数不是现读全量，
   现读全量与 86 那一档的口径见 §4.1）是可接受的现状，人不据此判红；新增一枚不带码的留痕会顶破 §四 那一行，
   逼人来**补码或在 §三 认领**——⛔ 不是靠抬上限收场（裁定 `20261012` §二 判例 A：AF 替自己签上调，正是这条棘轮立起来要堵的形状）。
6. **读者告示（裁定 20261011 §3 Q13 丙的乙半边，2026-10-11 半边落地：文档与真源常量已就位，机器脸挂载未落）**：内存审计台账里**除 `DEPLOY_AUDIT` 之外的三族**
   （`runtime.audit` 等）**仅本进程生命周期内可查**——进程一死就没有，`stats()`／HTTP 响应读到的都是活进程的那份。
   ⛔ 这句不许被读成"按设计不需要持久化"：Q13 只裁了 `DEPLOY_AUDIT` 一族值得落盘（`{store_root}/deploy_audit.jsonl`，
   与 `write_conflicts.jsonl` 同一家族），其余三族的持久化口径**没被裁过**，所以这里既不自认闭环、也不自认按设计。
   同一句话有**真源常量**而不只是散文：`af_audit.AUDIT_SCOPE_NOTE`（判据 `test_scope_note_says_what_it_has_to`
   ＋ `test_scope_note_is_exported`，都在 `tests/unit/test_deploy_audit_persistence.py`）。⚠️ 但它**还没挂到机器脸上**——
   把 `audit_scope` 打进 `Runtime.stats()` 与 `af_service` 的 `simulate_track`／`_session_view`／`live_run` 那四张响应脸本批未落，
   成本、窗口与追认见 §七 问 6。今天读者能看到的只有这一条文档告示。

| 级别 | 语义（写这一条时我在承诺什么） | 是否代表需要人介入 | 现读存量 |
| --- | --- | --- | --- |
| `DEBUG` | 探测/旁路失败，主路径有兜底且结果不受影响；带 `exc_info` 供事后复盘 | 不需 | 见 §2.1 计数行 |
| `INFO` | 一次性里程碑（启动、模式切换、任务被接管）；正常运行里不该刷屏 | 不需 | 见 §2.1 计数行 |
| `WARNING` | 这一笔**做成了**，但触发了降级／拒收／兜底／被拒；**连续出现**才意味着要看盘 | 看频次 | 见 §2.1 计数行 |
| `ERROR` | 一次动作的取数或落盘失败，且**这一笔的结果**已经受影响（读到空图、退回全量、写不进去） | 需 | 见 §2.1 计数行 |
| `EXCEPTION` | 捕到了非预期异常（必然带 `exc_info`）；机制在挡，挡的是没预料到的形状 | 需 | 见 §2.1 计数行 |
| `CRITICAL` | 需要停机或人工恢复才能继续 | 需 | 见 §2.1 计数行（现读 0） |

三条细则：

- **`CRITICAL` 保持 0 是基线**，不是缺陷。这一档留给"整机不可用"，本仓今天没有这种判定；任何一枚升到
  `CRITICAL` 都会先顶破 §四 的上限，逼人在 §三 认领。
- **码是身份，级别是严重度**，两件事分开：§三 钉的是"这枚码存在、它在哪一级、谁认领"，
  §1.6 钉的是"这一级承诺了什么"。改级别＝改承诺，门会红（`level=` 对撞）。
- **"需要人介入"这一档的唯一去处是 §三 的 `介入：` 字段**。不在别处另立一份名单，否则又长出第二份真值。

   ```
   lg = logging.getLogger("uvicorn.error"); lg.addHandler(logging.NullHandler())
   logging.config.dictConfig(uvicorn.config.LOGGING_CONFIG)
   → dictConfig 前 uvicorn.error.handlers = 1
   → dictConfig 后 uvicorn.error.handlers = 0
   ```

   `uvicorn.run()` 内部走 `LOGGING_CONFIG` 的 `dictConfig`，而 `_clearExistingHandlers()` 会把该 logger
   的 handlers 清空 ⇒ serve 在 `uvicorn.run()` **之前**装的任何钩子，对这一族都活不过启动。
2. **挂到 root 上也接不到**（同一份配置的另一格）：

   ```
   uvicorn.config.LOGGING_CONFIG["loggers"]["uvicorn"]["propagate"] → False
   LOGGING_CONFIG["loggers"] 的键 → ['uvicorn', 'uvicorn.access', 'uvicorn.error']
   root 上临时 handler 收到的记录名 → ['httpx']        # uvicorn.error.error("X") 那一条没到
   ```

   `propagate=False` 让这一族的记录止步于自身，root 上的 handler 收得到同进程里 `httpx` 的 ERROR、
   收不到 `uvicorn.error` 的。
