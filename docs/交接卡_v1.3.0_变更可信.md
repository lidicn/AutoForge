# 交接卡 · v1.3.0 变更可信（diff 签名兜底 + 爆炸半径 + 归档归属）

> 依据：`docs/调研_autoflow对照_全模块.md` §2.3（diff 签名兜底）、§2.4（爆炸半径）、§2.5（归档归属）
> 动机：`af_store.diff_graphs` 纯按 node id 做集合差，而 AutoForge 的 node id（`a1`/`i1`/`d1`）是 **Agent 随手起的**——
> Agent 重写时把 `d1` 起成 `do1`，`forge diff` 就显示「删了 d1、加了 do1」，**实际是同一个节点**，人审无法判断真实变更。
> 前身 autoflow 有**双模式匹配**（id 一致→按 id+拓扑；不一致→按 `(type, 签名)` 贪心配对）。多 agent 接入前必须先有归属与爆炸半径。

## 2. 行为增量（与上一版的差异）

**核心**：让「变更了什么」可信、让「一次能改多少」有上限、让「谁建的归谁」有归宿。

### 2.1 diff 签名兜底

- `diff_graphs` 原纯按 node id 集合差；现 **id 集合不一致时退化到按 `(kind, action, 主 entity_id)` 贪心配对**，输出 `renamed_nodes`（标注 `matched_by=signature`）。
- 相关边一并归一化（不产生虚假的边增删）；签名全空的占位节点（`pass`）**不参与**兜底防误配；真·新增/删除仍如实报 `added` / `removed`。
- 签名匹配**只用于 diff 展示**，不改变 `store.load` 语义（id 仍是唯一键）。

### 2.2 爆炸半径

- 新增 `DEFAULT_BLAST_RADIUS = 8`（env `AUTOFORGE_BLAST_RADIUS` 可配）。
- `save_graph` / `enable_by_tag` / `import_store` 受影响实体数超阈值即拒（400「爆炸半径…」）。
- `enable_by_tag` **先算影响面再落盘**（拒绝时任何归档都不改，无部分写入）。
- 导入 bundle 等显式批量操作走 `allow_bulk=True` 放行（默认拒绝，避免误伤单条变更）。

### 2.3 归档归属

- Graph 归档元数据加 `owner` 字段（创建/持有该 version 的主体）。
- `save_graph` 接 `owner` 入参，`list_graphs` 暴露 `owner`。
- 已归属他人的归档被他人覆盖 → **403「所有权隔离」**；归属为空（`None` / `""` / `system`）视为公共放行。
- `af_mcp` 的 `af_save` 取当前令牌 `subject` 作为 `owner`，与 v0.8.0 `TokenRegistry.subject` 衔接。
- 注：ROADMAP 规划了 `created_by` / `owner` 双字段，实现以 `owner` 等价承载归属（`created_by` 由 `owner` 推导，未独立落库）。

## 3. 验证方式

```powershell
# 全量
python -m pytest tests -q
# 本版单测（13 条）
python -m pytest tests/unit/test_v1_3_change_trust.py -q
```

- **签名兜底**：节点 id 全改（`a1→on1` / `d1→do1` / `p1→end1`）后 `diff_graphs` 必须配对为 `renamed_nodes`（`matched_by=signature`），`added` / `removed` 不含重命名节点（`test_rename_is_not_added_plus_removed` / `test_rename_normalizes_edges`）。
- **边界**：`pass` 占位节点签名全空不参与兜底（`test_empty_signature_nodes_not_matched`）；真·新增仍报 `added`（`test_real_addition_still_reported_as_added`）；相同图 diff 为空（`test_identical_still_empty`）；`svc.diff` 结构化输出暴露 `renamed_nodes`（`test_service_diff_exposes_renamed_nodes`）。
- **爆炸半径**：env `AUTOFORGE_BLAST_RADIUS=2` 时 5 节点 `save_graph` 被拒（400），`allow_bulk=True` 放行（`test_save_graph_over_blast_radius_rejected`）；`enable_by_tag` 超限拒绝时**一个归档都没改**（`test_enable_by_tag_over_blast_radius_rejected_without_partial_writes`）；`import_store` 超限不落地（`test_import_store_over_blast_radius_rejected`）；`DEFAULT_BLAST_RADIUS == 8`（`test_default_blast_radius_constant`）。
- **归档归属**：`owner` 落盘并在 `list_graphs` 暴露（`test_owner_recorded_and_exposed`）；他人覆盖 → 403（`test_ownership_isolation_blocks_other_subject`）；公共归档任何主体可改（`test_public_archive_allows_any_subject`）。

## 4. 已知风险 / 残留项

- [ ] 签名匹配为贪心近似：极端「大量重命名 + 少量真删除」混用时配对顺序可能与人预期不同。**影响范围**：仅 diff 展示精度，不改变 `store.load`，不影响 Runtime 主链路。
- [ ] 爆炸半径默认 8 按典型家庭自动化规模设定；超大规模 bundle 须显式 `allow_bulk=True`（已设计，非回归）。
- [ ] `created_by` 未独立落库（`owner` 等价承载）；若后续需区分「创建者」与「当前持有者」再补。
- [ ] **NAS 容器复核未执行**：断开副本，需 `scp` + `restart` 后复核。
