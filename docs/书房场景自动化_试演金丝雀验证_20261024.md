## 意图 JSON（MCP af_draft 直喂）

```json
{
  "intent": {
    "name": "书房太热自动开空调",
    "when": {"type": "state", "entity": "书房温度计"},
    "if": {"and": [
      {"is_off": {"var": "书房门"}},
      {"or": [{"is_on": {"var": "书房射灯"}}, {"is_on": {"var": "书房吊灯"}}]},
      {"gt": {"var": "书房温度计", "const": 26.5, "type": "numeric"}}
    ]},
    "do_list": [
      {"action": "climate.set_hvac_mode", "target": "书房空调", "hvac_mode": "cool",
       "requires_confirm": true, "canary": {"auto_rollback": true}},
      {"action": "climate.set_temperature", "target": "书房空调", "temperature": 26,
       "requires_confirm": true, "canary": {"auto_rollback": true}}
    ]
  }
}
```

**为什么是两个 do 节点**：HA 的 `climate.set_temperature` 只设目标温度、不改运行模式；`set_hvac_mode` 才切
制冷。仿真底座（`af_vhass/fake.py` 的 `service_effect`）如实建模这个分工——单节点 `set_temperature`
不会把空调从 `off` 翻成 `cool`。两个节点各带 `requires_confirm`（L2 门禁要求）+ `canary`（P1-2 要求）。

## 为什么 canary 不带 duration

canary 带 `duration` 时动作下发后实例挂起观察，到期走 `resume("on_timeout")` →
`pick_edge(d3, {on_timeout, default})`。af_draft 生成的中间 do 节点**只有 then 出边**，
匹配不上 ⇒ 实例静默终止 ⇒ **链条后半段（设 26 度）永远不执行**（实测：trace 停在 d3，AC=cool 但
temperature 属性没写）。

这是 canary-observe 与 af_draft 边纪律之间的真实缺口（缺口册新增 G10），不是本场景的写法问题。
本轮规避：canary 只写 `{"auto_rollback": true}`（无 duration）⇒ 立即漂移检查、不挂起、链条照常往下走。
climate.set_hvac_mode/set_temperature 在 `DYNAMIC_SERVICES` 里（预期态由参数决定），
`expected_state()` 返回 None ⇒ 漂移不可判 ⇒ 记 `unmodeled`（诚实报告分层里的「无从验」，不是假绿）。

## 试演 + 金丝雀怎么进（现状与路径）

**试演（premiere trial）**：`af_apply` 的 save 阶段成功后自动 `enter_trial(store_diff_sha, hours=24)`——
即这条自动化经 MCP `af_apply` 入待批队列、出资人 WebUI 点批准的那一刻，自动进 24h 试演期
（只统计不封禁，`af_premiere.is_paused` 才会拦后续 apply）。**不需要额外操作**。

**金丝雀（canary）**：两个 do 节点都带了 `canary` 字段 ⇒ 真机下发时走 `CanaryGuard.perform`
（下发前取快照 → 调 adapter → 比对漂移 → `auto_rollback: true` 时反向下发回滚）。本轮写法无 duration
⇒ 立即检查。漂移判据对 climate 动态服务是 unmodeled（见上），回滚把手仍在。

**影子（shadow）档**：生产容器 `AUTOFORGE_CONF_GRADING=1` 已启用（v1.12.0 修的那格）。
shadow 档按 **confidence** 路由：`decision_for(conf)` —— conf≥0.85 → auto；0.60–0.85 → shadow；
<0.60 → ask。意图通道（af_draft）**不接受 confidence 字段**（`_INTENT_FIELDS` 白名单里没有它，
这是缺口册 #2 的老问题）⇒ 意图草拟的自动化 conf 缺省 1.0 ⇒ 直接落 auto 档，**不进影子**。

要走影子档有两条路：
1. 手写 IR 顶层带 `"confidence": 0.7`（schema 支持，`Automation.confidence` 读它）——不走意图通道；
2. 等 #2 修了（意图白名单加 confidence）再走意图通道。

本条场景**没进影子档**，走的是 auto 档 + 节点级 canary + L2 双确认。要影子的话告诉我就按路 1 手写 IR。
