## 2. 行为增量（与上一版的差异）

**核心**：v1.1.0 已把「自然语言 → entity_id」的**检索层**做进平台；本版补**决策层**——多路由选哪个、弱信号别用、怪异设备别被埋没、选过的记住。

### 2.1 集成优选（`connectivity_tier`）
- 从 `integration`（无则 `platform`）子串推导 **`local` > `cloud` > `polling` > `unknown`**（如 `xiaomi_miot`→local、`xiaomi_home`→cloud、`template`→polling）。
- 排序在**置信度之后**插入一个键：**不改 fail-closed 纪律**（置信度仍是第一优先）。
- ⚠️ **未知档位一律中性**（`unknown` rank=3，等同不排序）；**只影响排序，绝不过滤**。无注册表数据（未装 `websockets`）时全部 `unknown` → 顺序与 v1.1.0 完全一致（零破坏）。

### 2.2 device 归并（设备卡）
- `resolve` 结果新增 **`devices`**：按 `device_id` 把同物理设备的多 `entity_id` 合成一条设备卡，含 `preferred_entity_id`（=卡内首条，即集成优选后的首选路径）与 `paths[]`。
- ⚠️ **归并只影响展示**：`entity_id` 仍是唯一键（IR / `store.load` 语义不变）；无 `device_id` 的候选各自成卡。
- 所有出口（含别名直中、entity_id 精确命中）都带 `devices`（`_finish` 统一挂）。

### 2.3 弱信号降权（P1）
- `offline_now`（state ∈ unavailable/unknown）→ 排序**再降一档**（只降权不过滤），并在候选上给 **`health_note`**。
- 结果 `note` 显式回传：「设备 Y 当前不可用，建议优先 X（integration）」；全离线则提示谨慎使用。
- **长期健康度仍归 MA**（AF 只做此刻可用性，无常驻采样）。

### 2.4 别名沉淀（`{root}/.catalog/aliases.json`）
- `set_alias(name, entity_id)` 落精确映射；`resolve(name)` 命中即**直中**（`matched_by="alias"`、`confidence="high"`、`bucket="exact"`），不再每轮重排/误选。
- 出口：MCP `af_remember_entity`（write）、HTTP `POST /api/catalog/alias`、CLI `forge entities remember`；查看/删除同理。
- `set_alias` 校验 `entity_id` **必须已在本机目录中**（防沉淀幽灵 ID）。

### 2.5 联动验证闸（P2，设计 §3 P2 第三项）
- 新增诊断码 **`ENTITY_OFFLINE_NOW`**：`build` / `save_graph` / `submit_pending` 的静态扫描时，
  若引用的实体在目录里被标为「此刻不可用」（`offline_now`，state ∈ unavailable/unknown）→ **显式告警**
  （level=**warning**，附 `hint`「会让自动化假绿（sim 通过、真机不生效），建议改用在线候选或先恢复设备」）。
- **只告警不拦截**（`ok` 仍为 True）：设备可能只是临时离线，**静默替 Agent 判死是更大的错**。
- 数据源 `DeviceCatalog.health_map()`（快照内的此刻可用性，零常驻采样）；**目录为空/读取失败 → 空视图，零误报**（离线编写 IR 场景行为不变）。
- 与 §2.3 呼应：解析侧「降权 + 标注」，验证侧「标记 + 提示」——同一份 `offline_now` 事实，两侧共享。

### 2.6 可选 binding（决策 3）：设备描述占位符 → entity_id
- **可选、不强制**（保住「离线编写 IR」与 G7 AF-Spec 零有损往返）：不启用时 IR 必须写精确 entity_id，行为与 v1.1.0 **完全一致**。
- 占位符约定：`entity_id` 以 `?` 开头，形如 `?书房吊灯` 或 `?light:书房吊灯`（域收窄）。
- `svc.bind_ir(store, ir)` 遍历 `trigger.entity_id` / `params.entity_id`（含 list）/ `expect[].entity_id`，
  命中则**回填真实 entity_id** 并返回 `bound[]`。
- **fail-closed 纪律不变**：歧义（多候选且 top 非 high）/ 无候选 → **不回填**，保留占位符并记 `unresolved[]`，
  交由既有安全闸（未知实体）拒编译；**绝不静默猜域/猜实体**。
- 出口：CLI `forge build --bind [--root]`（打印已绑定/未绑定）、HTTP `POST /api/bind`。

## 3. 验证方式

```powershell
python -m pytest tests -q
python -m pytest tests/unit/test_v1_6_decide.py -q
# CLI 冒烟
forge entities remember "书房灯" light.study_lamp --root .forge
forge entities aliases --root .forge
forge entities forget "书房灯" --root .forge
```

- **集成优选**：同 `device_id` 双集成（`xiaomi_miot` 本地 / `xiaomi_home` 云）→ 候选首条为本地，且 `devices` 归并为**一条卡**、`preferred_entity_id`=本地那条。
- **弱信号**：离线候选排后（在线优先），`health_note` 非空，`note` 含「不可用…建议优先…」。
- **别名**：未沉淀 → `bucket=none`；沉淀后 → `bucket=exact`、`matched_by=alias`、`confidence=high`；`list_aliases`/`remove_alias` 生效。
- **接线**：MCP `af_remember_entity` 需 `write` scope（只读令牌 → isError）；HTTP 三端点；CLI 三命令。
- **验证闸（P2）**：`svc.build(IR_引用离线实体, store=…)` → `warnings` 含 `ENTITY_OFFLINE_NOW` 且带 `hint`，`ok` 仍 True；在线实体不报；无目录零误报；`save_graph` 出口同样带该告警。
- **binding（决策 3）**：`?玄关灯`（唯一）→ 回填 `light.hall`；`?light:书房吊灯`（域收窄）→ 回填 light 那条；`?吊灯`（歧义）→ **不回填**（`ok=False`、`unresolved` 含「歧义」、占位符原样保留）；无占位符 → `total=0` 零改动；CLI `--bind` 打印「已绑定」；`POST /api/bind` 返回同构结果。
