# 进程模型清单（生命周期站点 × 同步原语 × 共享状态归属）

> 本文件由 `scripts/check_process_model.py` 把「谁拉起进程、谁负责收、哪份状态归谁」变成**可 diff 的资产**。
> 起因是第六轮审计 ARCH-06：报告说这仓「三套互不相识的同步原语 ＋ 无 supervisor ＋ 无优雅停机」，
> 且「没有等价物锁住『共享可变状态的归属』」。前两句有格已经过期（见 §五），第三句成立——本清单就是那把锁。
>
> §二 是自动段（跑 `--write` 重生成，勿手改）；§三／§四 是手工登记；§五／§六 是复测与递裁记录。

## 一、口径与射程

1. **射程**：`src/autoforge/*.py`（整棵，只 `ast.parse` 不导入）。`scripts/` 与 `tests/` 里的子进程
   **不在射程内**——它们是一次性工具与判据自身，不是常驻运行时的组成部分；这一格明写而不是静默排除。
2. **生命周期站点**＝代码里能改变进程/信号/退出时序的十四个调用形状（`KINDS`，见脚本 §头）。
   多数今天为 0，那是**基线**不是噪音：任何一枚从 0 变 1，都必须先在 §三 认领"谁负责收"。
3. **同步原语**＝`threading.Lock/RLock/Semaphore/Condition`（进程内）＋ `FileLock`（跨进程）。
   本清单只登记**站点**（在哪、绑到什么名、包围在哪个函数），不判"该不该加锁"——后者是运行时语义。
4. **模块级共享名**＝被某个函数用 `global` 改写过的模块级名字。这是"哪份状态归谁"的最小机械口径：
   它比"所有模块级可变绑定"（现读 85 枚／33 个文件）窄得多，因为后者一大半是常量表（`_TIER_RANK` 那类），
   改不动也就无所谓归属；真正会被运行期改写的是 `global` 那一小撮。
5. **门判的是对账，不是缺陷**。§二 里"函数体内没有任何 `with`"的那些行不等于 bug（写一次的懒加载单例
   在 GIL 下引用赋值是原子的），它等于"这一份状态的归属被人核看过、写在这里"。
