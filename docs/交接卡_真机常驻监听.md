## 2. 行为增量（与上一里程碑 R2 的差异）

- 新增能力：AutoForge 从"回放式一次性"升级为**常驻运行**——`forge watch` 启动后持续订阅 HA `/api/stream`，每个 `state_changed` 实时进入 `Runtime.publish` 评估自动化；后台线程按 `--tick-s`（默认 1s）周期 `runtime.tick()` 驱动 `for`/`wait` 计时器。
- 对外契约（CLI）：新增 `forge watch` 子命令，选项 `--entities/--acl/--ha-url/--ha-token/--confirm/--live-allow/--tick-s`，语义与 `run --live` 同口径。
- 无 IR Schema 改动、无既有 CLI 行为变化。

## 4. 已知风险 / 残留项

- [ ] **初始状态冷启动**：`watch` 启动时不主动拉全量状态快照；依赖首个 `state_changed` 与执行期按需 `snapshot()`。若自动化首触发需"上个状态"，首拍可能缺上下文（与 `run --live` 同现状，非本里程碑引入）。
- [ ] **HA SSE 仅推送 `state_changed`**：`HAEventBus`/`event` 类型事件（如 `call_service`）不进总线；当前 `BusEvent` 订阅为精确匹配，无通配（KICKOFF §4.1 红线），未扩展。
- [ ] **多实例/跨进程**：Runtime 仍为单进程内存态；`watch` 进程退出后活跃实例丢失（与 G1 红线一致，P1 话题）。
- [ ] **并发 watch 多自动化**：单 Runtime 内多自动化共享总线/调度器，已具备；多 Runtime 多进程需外部编排（后续）。
