## 一、本轮 findings（1 条）——成立，已改码

### 缺陷 · 四个 `StateProvider` 两派策略，仿真与生产对同一 IR 结论相反

**核实：成立，且是七轮里第一个打在"接缝"上的真缺陷。** 报告给的定位逐条对得上 HEAD：

| 实现 | HEAD 位置（修复前） | 修复前策略 |
|---|---|---|
| `InMemoryStateProvider` | `af_state.py:112` | 抛 `UnknownEntity`（源码注释 P1-12） |
| `FakeHA`（`forge sim` 底座，`af_cli.py:353` 注册） | `af_vhass/fake.py:75` | 抛 |
| `HAStateProvider`（生产 REST） | `af_adapters/ha.py:195` | `if entity_id not in all_states: continue` **静默省略** |
| `HassStateProvider`（生产 `hass.states`） | `af_vhass/bridge.py:35` | `state is None → continue` **静默省略** |

报告的短路机理也复核过：`af_ir/expr.py:514-517` 的 `and`/`or` 用 `all()`/`any()` 生成器表达式，
左侧定胜负时右侧**根本不被求值**，所以"缺失留给运行时去发现"在 fail-open 一侧不成立。
（报告写的 `expr.py:483` 是快照行号漂移，机理一致。）

**修复方向取报告推荐的"全部 fail-closed"**，并把四处落点都做了一遍（不是只改 provider）：

1. `af_adapters/ha.py:195`、`af_vhass/bridge.py:35`：未知实体在 `snapshot()` 这一刻抛
   `UnknownEntity`，与仿真底座同口径。
2. `af_state.py:87` `StateProvider` 协议补**跨实现契约**（含"为什么必须在取快照时拦"的短路理由），
   新增实现必须进契约测试的表。
3. `af_canary.py:88` `has_drift()`：动作后读不到目标 → 保守判**有漂移**（读不到 ≠ 验过了，
   铁律 #5），并把异常收在 canary 内部——原先抛出会穿出 `executor.step()` 拖垮整次 tick。
4. `af_executor.py:509` `do` 节点取不到动作前快照 → `UnknownEntity` 走 `_soft_fail`
   （记 `entity_drift` + 走 `on_error`），**一条动作都不下发**：没有快照就没有回滚把手（铁律 #5）。
5. `af_service.py` `live_run` 的终态读取改成 `_live_final_states()`：这是**报告**路径
   （动作已下发、`undo_deploy_id` 已落盘），缺实体翻成返回体里的 `missing_entities`，
   不让一次成功部署变成 500——500 会让操作员连撤销把手都拿不到。

**测试**：
- 新增 `tests/contract/test_state_provider_policy.py`（14 例）：四实现同口径、齐全时不误伤、
  审计原式 `or(is_on(motion), is_on(ghost))` 四边结论一致，另附两例反证（铁律 #8）——
  撕裂快照确实会让 `or` 判 True（说明为什么口径只能定在取快照时）、fail-open 桩确实能把
  本契约判红。
- `tests/unit/test_af_canary.py` 追加 2 例（动作后实体消失判漂移、取不到前置快照不下发）。
- `tests/unit/test_af_undo_http.py` 既有端到端例加断言：漂移实体在 `missing_entities` 里点名、
  `final_states` 记 None、`undo_deploy_id` 仍交回前端。

### 副作用（必须记账，不自签）

统一到 fail-closed 的代价在 `af_instance._refresh_snapshot`：`snapshot()` 抛时回退成**空快照**，
于是"单个读取实体漂移 = 该实例这一整段读不到任何状态"，而不是"只有引用它的那一支失效"。
仿真侧从 P1-12 起就是这个口径，本轮把生产侧对齐过去（这正是"两边不许一半一半"要求的）。
是否改成"逐实体可见的漂移"（快照保留可读子集 + 显式 missing 集合 + 表达式三态）是产品语义裁定，
已投 DCD：`关键决策部/inbox/20261002-AF-StateProvider统一fail-closed的方向与代价-决策申请.md`。
裁定未回之前，本改动**只在本地/测试链路**，生产 NAS 不部署（铁律 #3）。
