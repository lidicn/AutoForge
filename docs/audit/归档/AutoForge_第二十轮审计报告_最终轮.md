## 一、本轮新增：W46 探针自保与性能

### W46c：探针必须能自保

`af_nl_parse.py:1188 _build` 从第十九轮起反复让整个沙箱 HTTP 502。而**手工单独跑它只要 1.5–2.4 秒**（and/or 两形态 × 5 个深度档共 10 次调用，全部 `AttributeError`，无崩溃）。

这说明失控的是**探针宿主进程**，不是被测函数。已加：

```python
resource.setrlimit(resource.RLIMIT_AS,   (2_000_000_000, 2_000_000_000))  # 2GB
resource.setrlimit(resource.RLIMIT_CPU,  (60, 60))                        # 60s CPU
```

**加完仍复现**，根因未定位。这跟第八轮"状态损坏探针写坏工具链源文件"是同一族问题——**探针缺少对自身的约束**。被测代码没有深度预算，那探针自己必须先有预算。

### W46a：形态试探不再叠加到深度阶梯

第十九轮把多形态试探加在**每一档深度**上，每目标子进程数 5 → 10，单轮跑不完、多次超时。

但形态差异只在**环**上体现（`and` 分支可能完全不递归，`or` 分支直接递归），线性深嵌套走同一条递归路径，换 op 不改变深度行为。改为 **cyclic 跑全形态、深度阶梯只跑首形态** ⇒ 子进程数 10 → 6，结论强度不变（崩在哪个形态仍记在 cyclic 上）。

### W46b / W46d / W46e

- **b**：同一 `(module, function)` 只测一次（此前不同行的多条命中会重复跑整套探针）
- **d**：cyclic 阶段判 error 后不再跑满 4 档深度（形状不匹配的 error 换深度也不会好转）
- **e**：逐目标 flush 进度日志——没有进度就只能瞎猜卡在哪一个上

`scripts/` 漏扫 · 写盘别名缺失 · RES-03 全文件正则 · 抑制锚点行号漂移 · glob 跳过点目录 · `_fetch_stub` 实体不全 · 补丁少导入被宽 except 吞 · bandit 认不出间接调用 · 外部工具跨调用丢失 · `NestStandin` 空迭代 · **探针卡死宿主（本轮）**

失效源从"我们写的分析器"→"补丁"→"外部工具"→"环境"→**"探针自身"**，位置一路外移。唯一有效的对策是一条纪律：**任何"看起来修好了"或"看起来没了"，先怀疑工具与环境，再相信结论。**
