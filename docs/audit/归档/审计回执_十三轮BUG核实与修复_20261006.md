- **核实对象**：`docs/audit/` 下 19 份 `审计报告-*.md`（含一份最终轮复核）
- **报告基线**：commit `f0184de9`（2026-10-05）
- **核实基线**：commit `9742102` + 本轮改动

- **核实方式**：逐条读报告的「确证缺陷」小节 → 回到**当前**源码取样对照 → 能引用出
  报告描述的缺陷形状才判 `STILL_PRESENT`；修好后重跑门禁与全量测试。

### 顺带修掉的两个真实缺陷

- **`af_metrics.py` 缺 import**：BUG-04 的修复代码用了 `logger` 与 `atomic_write_text` 但**两个都没
  import**，走到「缓冲有坏行」那条分支就是 `NameError`。被 `test_undefined_name_gate` 判红后补上。
  这一条报告没记，但确实会炸。
- **判据 E 自身的两个缺陷**（跑出来才发现，已写进门禁注释）：
  ① 豁免理由**必须写在同一行**——收集是逐行扫的，跨行理由匹配不上；
  ② 射程锚点不能只数「裸写」：全都改走助手后 `in_scope` 归零，反空洞自证会把
  「修干净了」误判成「射程失效」。锚点与红行已解耦。

## 四、回归

本轮动了 group 渲染与门禁两处公共路径，回归面比一般改动宽，逐条都钉了：

- `test_af_ir_group.py` / `test_af_ir_group_mode.py`：group 渲染从「节点指针 + 独立【组合】段」
  改成**就地内联**（`编组（mode · 措辞）` + `子自动化「name」`），两处措辞断言
  （`依次按序下发` / `可并行下发`）由双写形式保住；**无 `on` 入口、group 不可达**的图补了
  兜底渲染（否则整条自动化渲染成空壳、覆盖率报 missing）。
- 兜底渲染第一版漏了两件事，都已修：① 没把 group 记进 `covered`；
  ② 在 group 分支 `return` 会**吃掉 group 的出边**（`n_group → n_pass` 的收尾节点不渲染，
  `tests/f14` 样本 #27 就是这一类）。
- `tests/unit/test_bounded_caches_gate.py`：`af_nl_parse.py` 带来的 6 个新容器已逐个就地豁免
  带理由（3 个 import 期填满的静态反查表 + 3 个单次解析累加器），因此把钉住的读数
  75 → 81；BUG-21 收口（20261006）关闭 dataclass 字段容器盲点后扫到数 81 → 122、基线 73 → 114，
  钉住读数与 docstring 同步更新（不是拿数字抹平）。
- `tests/unit/test_atomic_write_gate.py`：判据 E 必须**独立开关**——原先挂在 `AUTH_LEG_ROOT`
  下，测 D 腿时把该开关指向临时树会把 E 一起启动，在「临时树没有状态落盘点」上 exit 2，
  把 D 腿读数带崩。这与 `SRC` / `AUTH_LEG_ROOT` 那个耦合同构，已加 `STATE_LEG_ROOT` 拆开。
