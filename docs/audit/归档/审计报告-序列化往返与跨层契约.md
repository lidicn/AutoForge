## 三、确证缺陷

### 🔴 BUG-12（高危）`af_instance._transition()` — 先改状态后自检，失败留下半迁移脏实例

**位置**：`src/autoforge/af_instance.py:400-407`

```python
def _transition(self, instance, target, allow_from_terminal=False) -> None:
    current = instance.ctx.state
    if current in TERMINAL_STATES and not allow_from_terminal:
        raise IllegalTransition(...)
    if target not in _ALLOWED[current]:
        raise IllegalTransition(...)
    instance.ctx.state = target      # ① 先改状态
    instance.to_dict()               # ② 后做序列化自检 ← 抛异常时 ① 已生效
    self._sync_timers(instance)      # ③ 永不执行
    self._notify(instance)           # ④ 永不执行（Runtime 的落盘回调）
```

`Instance.to_dict()` 是严格的 JSON 序列化自检（注释写明 P2-3 特意移除 `default=str`，改为 fail-fast 以防不可序列化对象被静默字符串化）。但它在**状态已被改写之后**才执行。

#### 实测复现

往 `ctx.vars` 混入 `datetime`（P2-3 想防的正是这类对象），执行 `CREATED → ACTIVE`：

```
迁移前 state = created
_transition 抛异常: TypeError Object of type datetime is not JSON serializable
迁移后 state = active   ← 已被改成 ACTIVE
on_change 通知次数 = 0   （Runtime 落盘回调从未触发）
timers = []              （未同步）
```

**二次影响更严重**——清掉脏值后继续迁移：

```
① 失败后 state = active   落盘触发次数 = 0
② 二次迁移 ACTIVE→DONE 成功，state = done   落盘次数 = 1
落盘记录的状态序列: ['done']
>>> created→active 这一步从未落盘
```

#### 后果

1. **内存与磁盘分叉**：`on_change` 是 Runtime 把 `persist=true` 实例落盘的回调（`:188` 注释明写）。自检失败时它不触发 → 内存里是 `active`，磁盘上仍是 `created`。重启后实例按 `created` 恢复，与崩溃前的实际执行进度不符。
2. **状态机被跳过一步**：由于 `state` 已被改成 `active`，后续从 `active` 出发的迁移**合法通过**，`created→active` 这一步的语义（初始化、计时器设置）被整体绕过。
3. **异常向外传播**：调用方（如 `resume`/`activate`）收到 `TypeError`，但实例已处于脏状态，重试会把"跳过一步"固化。

#### 讽刺之处

P2-3 的修复**方向是对的**（去掉 `default=str`，改严格序列化），但**自检位置放错了**：

| | 现状 | 后果 |
|---|---|---|
| 有 `default=str` | 脏对象被静默字符串化 | 恢复时解包崩溃、回滚静默失效（P2-3 想修的） |
| 去掉后但位置错 | 脏对象导致**状态半迁移** | 内存/磁盘分叉、状态机跳步（新问题） |

**它防住了「脏对象被静默字符串化」，却引入「脏对象导致状态半迁移」。**

#### 修复建议

自检必须在改状态**之前**：

```python
def _transition(self, instance, target, allow_from_terminal=False) -> None:
    ...校验...
    instance.to_dict()               # ① 先自检：失败则状态完全未动
    instance.ctx.state = target      # ② 再改状态
    self._sync_timers(instance)
    self._notify(instance)
```

若因性能不能每次自检，则失败时必须回滚：

```python
    instance.ctx.state = target
    try:
        instance.to_dict()
    except Exception:
        instance.ctx.state = current   # 回滚
        raise
```

前者更干净（fail-fast 且状态不可观测地被改）。

## 四、已核验为良性 / 设计取舍

| 规则 | 命中 | 核验结论 |
|---|---|---|
| SER-01 单向序列化 | 11 | `AuditEvent`/`EvoProposal`/`SimOutcome`/`DimScore`/`HealthResult`/`InsightRecord`/`InstanceTimer`/`InstanceContext`/`Instance`/`RegistrySnapshot`/`Snapshot` —— 核验这些类所在文件**均无 `from_dict` 需求**（`from_dict` 出现次数全为 0），属"只出不进"的导出型/只读型结构，**非缺陷** |
| SER-02 键漂移 | 1→**0** | `AskSpec` 为假阳性：`to_dict` 用增量赋值写 `min`/`max`/`unit`，`from_dict` 读同名键，实际一致。修正分析器后消除 |
| SER-03 字段未序列化 | 1 | `AskSpec` 同上的残留：`min_`/`max_`/`unit_` 按 IR schema 去下划线输出（`to_dict` docstring 明写"回写为 IR 形态（`min/max/unit` 无下划线，与 schema 一致）"）；`prompt` **刻意不序列化**（docstring 明写"不由 IR 的 ask 对象携带……避免两处真相"）。**均是有意设计，非缺陷** |
| SER-04 不可 JSON 类型 | 1→**0** | `InstanceContext.to_dict` 为假阳性（`self.timers` 被 `time` 前缀命中）。修正词边界后消除 |
| SER-05 `default=str` | 8 | 均在日志/遥测/MCP 回执等**展示路径**，静默转字符串是可接受的降级（且 R-57 有意不回传 traceback）。与 P2-3 在**持久化路径**上去掉 `default=str` 并不矛盾——两条路径的容忍度本就不同 |
| SER-07 状态码种类 | 1 | 仅为提示，需人工确认；未发现同类错误映射到不同码的确证案例 |

**关于 SER-05 与 P2-3 的关系**，值得单独说一句：同一个 `default=str`，在持久化路径是 bug（P2-3 已修），在日志/回执路径是合理降级。所以 SER-05 的 8 处我不升格——**判据不是"用了 default=str"，而是"这条路径的数据会不会被反序列化回来"**。这正好呼应第九轮研究报告的结论：横切约束的门禁必须**按路径语义分层**，不能全局一刀切。

### BUG-12 补上了第六类根因：「操作顺序」

前九轮归纳出五类根因，BUG-12 是第六类，且是最普遍的一类：

| 场景 | 现状顺序 | 安全顺序 |
|---|---|---|
| `import_bundle(overwrite)`（BUG-11） | 删旧的 → 写新的 | 备份 → 写新的 → 成功才删 |
| `_transition`（BUG-12） | 改状态 → 自检 | 自检 → 改状态 |
| 落盘 vs 校验 | — | **未发现倒置**（TX-03 零命中，正面结论） |

三条里有两条做错。这比"忘了加锁"更隐蔽——**每一步单独看都合理，错的是它们的先后**。第九轮研究报告建议的「不可逆操作前先备份」正是同一原则的另一种表述。
