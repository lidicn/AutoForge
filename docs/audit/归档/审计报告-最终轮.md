## 三、🟠 BUG-21（medium）有界缓存门禁漏检全部 dataclass 字段容器

**位置**：`src/scripts/check_bounded_caches.py` → `_scan_class()` + `_is_empty_container()`

### 门禁的设计是对的

项目把第六轮审计的一句话（"新增有界缓存必须同时给 TTL 与硬上限，并在测试里断言"）变成了：

- `af_bounded_caches.py` 注册表：每项登记**两条腿**（cap 常量名 / trim 方法名）+ 一条真实测试 id
- 门禁脚本按名字回源码核对——**写不出那条腿就不许登记**（原文："不允许用注册表给一个说法盖章"）
- 判据 C：每个增长容器必须 ∈ 注册表 ∪ 固定键表 ∪ 冻结基线，否则判红

这个设计水平很高，比常规 lint 严格得多。

### 但它扫不到我确证的三个无界容器

实测 `--print-baseline` 输出 77 个容器，`af_conf.py` / `af_health.py` / `af_intervention.py` **三个文件零命中**：

| 确证缺陷 | 容器 | 声明写法 | 被扫到？ |
|---|---|---|---|
| BUG-14 | `ConfidenceStore.samples` | `samples: dict[...] = field(default_factory=dict)` | ❌ |
| BUG-18b | `HealthEngine.demote_errors` | `demote_errors: list[dict] = field(default_factory=list)` | ❌ |
| BUG-18a | `InterventionDetector.records` | `records: list[...] = field(default_factory=list)` | ❌ |
| BUG-01 | `NodeExecutor.node_visits` | （在 `__init__` 里） | ✅ 但**冻结在基线**被豁免 |

### 双重漏检根因

```python
# _scan_class 只认 target 是 self.X 的 Attribute：
elif isinstance(node, ast.AnnAssign) and node.value is not None \
        and isinstance(node.target, ast.Attribute) \
        and node.target.value.id == "self":        # ← dataclass 字段 target 是 Name！

# _is_empty_container 不认 field(...)：
CONTAINER_FUNCS = {"dict","list","deque","set","defaultdict","OrderedDict"}
if isinstance(node, ast.Call) and _call_name(node) in CONTAINER_FUNCS:
    return not node.args                            # ← "field" 不在表里
```

dataclass 字段是**类级 AnnAssign、target 为 Name、初值是 `field(...)`**——两条判据全不匹配。本项目大量使用 dataclass，这类容器**整个品类在射程外**。

### 两条逃逸路径叠加

- 扫得到的（如 `node_visits`）→ 被**冻结基线**豁免，永远不判红
- 扫不到的（如 `samples`）→ 连基线都进不去，也永远不判红

**结果：四个确证的无界容器，没有一个会被这个门禁拦下。**

### 附带发现：判据 B 失效却仍判绿

判据 B（测试必须钉住回收）因缺 pytest **无法核对**，脚本只打印一行"射程"警告，然后 **rc=0 判绿**。

这违反我在第九轮研究报告里提出的原则：**门禁必须区分"已合规 / 已违规 / 无法证明"三态，锚点缺失时不得返回绿**。这里恰恰把"无法证明"当成了"已合规"。

### 修复建议

`_scan_class` 增加对**类级 AnnAssign 且 target 为 Name** 的处理；把 `field` 纳入 `CONTAINER_FUNCS` 并识别 `default_factory=list/dict/deque`。判据 B 缺 pytest 时应**非零退出**或明确标记 `inconclusive`。

### 贯穿二十轮的一句话

> 这个项目**不缺正确的写法，也不缺把正确写法制度化的意愿**（16 个架构门禁 + 有界缓存注册表就是证明），缺的是**让机制覆盖到全部形态**。

证据链在最后两轮变得完整：

- 第九轮：我建议建横切约束门禁
- 第二十轮：发现项目**已经建了**，而且设计水平很高（"不允许用注册表给一个说法盖章"）
- 但它漏掉了 dataclass 字段这个品类 → 我确证的三个无界容器全部逃逸

这与 BUG-05（原子写门禁只审"已在做原子替换的站点"，漏掉"压根没走原子写"）是**同一种形状**：**门禁在守它看得见的那半边**。

## 七、审计方法论总结（可复用）

二十轮沉淀的六条：

1. **报 0 必须先自证**。"规则坏了"和"代码干净"外表完全一样，第十五、十六轮都靠合成样例抓住了失效的检测器。现在固化为开工门禁。
2. **静态给候选，实测给确定性**。确证缺陷几乎全靠实测（OOM、16/30 陈旧读、时钟回拨、640× 退化、配对失败）。候选不实测不升级。
3. **判据在被调方语义里**。第十轮 `default=str`、第十七轮 except 内调用，都验证了：调用点形状无法判定，必须看被调方。
4. **规则要判"不一致"而非"缺失"**。第十九轮 RMW-01 判"同类内有的重读有的不"，自动区分"有意都不重读"与"漏了一个"。
5. **先修规则，再考虑白名单**。第二十轮 P14 修规则成功（clean 归零且 dirty 未丢），P15 确实无法表达才进白名单。
6. **命中要 triage**。92.2% 的重复率说明：没有去重的"命中数"是虚荣指标。
