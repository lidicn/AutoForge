## 一、本轮 findings（2 条）——全部为真，全部改码

### 缺陷 1（中）· `_SESSIONS` 写入路径不回收 → 放弃的会话永久残留

成立。报告的「修复只需一行」也成立，但**只补一行不够**：TTL 那条腿要求"有人在读"，
而报告自己给出的触发场景就是"创建后不再读"。所以按同族三处（`af_audit` 的
`deque(maxlen)` / `af_preference` 的 `max_records` / `af_bus` 的 pop 驱逐）的口径补齐两条腿：

- `create_session` 建 Runtime **之前**先 `_purge_sessions()`（Runtime 挂着 bus/audit/adapters/clock
  的完整对象图，先清再建才不会把峰值抬到"创建速率 × TTL"）；
- `SESSION_MAX`（默认 128，`AUTOFORGE_SESSION_MAX` 可配）：超线时最老的先走；
- `_get_session` 的裸读纳入同一把 `_SESSIONS_LOCK`。

测试：`tests/unit/test_af_session_bounds.py`（5 例，含"纯创建不读也必须被回收"这一条
就是报告的触发场景）。

### 缺陷 2（语义）· `_jaccard(∅,∅) = 1.0` 把「共同缺失」读成「完全相同」

成立，且**上一批处置时漏了这条**——它是本轮两条 findings 里唯一没跟着 `create_session`
一起改的。数学上是 0/0，实现取了 1.0；实测对照确实是"两条都没写 trigger = 1.000"，
而"不同房间的人体传感器"只有 0.500。**任何阈值化去重都会把最容易误合并的一对排在最前面。**

修法取报告建议的第一种（空集返回 0.0），第二种「不可比较」标记要新造一个三态返回、
波及全部调用点，不值。改动在 `src/autoforge/af_evo.py`：

- `_jaccard`：任一侧为空 → `0.0`；
- `trigger_similarity`：任一侧拿不出 trigger → `0.0`（原式 `1.0 if (not sa and not sb) else 0.0`）。

**同时保留一处刻意的"共同缺失视为相同"**：`_detect_merge` 里 `sim = 1.0` 走的是
`EvoPolicy.merge_allow_empty_triggers` 这条显式策略位（默认 `False`，空触发不合并、防误吞），
不是从 Jaccard 顺出来的。语义修正后它仍然成立，测试
`test_merge_allow_empty_triggers_option` 就是钉这一点的：默认关、开则 1.0。

测试：`tests/test_af_evo_strategies.py::test_missing_triggers_are_not_identical`
（含 0.5 对照组）。反例（铁律 §五 #8）：把 `_jaccard` 的空集分支改回 `return 1.0` →
该测试即红 `assert 1.0 == 0.0`；恢复即绿。**已实测，两端都真跑过。**

## 三、建议（不当缺陷处理）

**「'只增不减' 已在 5 个模块复现，缺一个统一生命周期约定，建议引入 `BoundedCache` 基类」**——
判断成立，但落地方式我不选"新造基类"：

- 四处现状已经是"超时 + 硬上限"两条腿（`AuditLog`/`_records`/`_last_state`/本批 `_SESSIONS`），
  唯一漏的就是本批修掉的 `_SESSIONS`；
- 抽基类要改 5 个模块的存储层，而它们各自还挂着持久化格式（`af_audit` 落盘 JSONL、
  `af_preference` 落盘记录），统一基类的收益在可观测的内存曲线上看不出来，风险在持久化兼容上；
- 所以把它记成**约定 + 门禁可见**，而不是重构任务：新增有界缓存必须同时给 TTL 与硬上限，
  并在测试里断言"纯写不读也必须被回收"。这条约定就写在本文件里，作为审计与后续开发的对照点。

如果 DCD 认为应当升级为硬要求（统一基类 + 门禁扫描无界容器），那是一次跨模块重构，
需要变更窗口，走 `AF联动执行记录` 的窗口口径统一排队；本轮不动。
