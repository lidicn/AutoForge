## 三、确证缺陷

### 🔴 BUG-08（高危）`af_catalog.py` — 目录缓存以 `(mtime, size)` 为键，且 `_save()` 写盘后不失效缓存

**位置**：`src/autoforge/af_catalog.py:270-290`（`_load`）、`:293-301`（`_save`）

```python
def _load(self) -> dict[str, Any]:
    stat = path.stat()
    cached = self._cache
    if cached is not None and cached[0] == stat.st_mtime and cached[1] == stat.st_size:
        return cached[2]          # ← 命中即返回旧解析结果
    ...
    self._cache = (stat.st_mtime, stat.st_size, parsed)
    return parsed

def _save(self, payload) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    atomic_write_text(path, json.dumps(payload, ensure_ascii=False, indent=2))
    # ← 没有 self._cache = None，也没有更新缓存
```

**两个问题叠加**：

1. **缓存键粒度不足**：`(mtime, size)` 在本沙箱文件系统上分辨不出快速连续写入。实测 20 次连续 `_save()` **只产生 7 个不同的键**——13 次写入在缓存看来"文件没变"。
2. **写盘不失效缓存**：`_save()` 是本项目自己的写入路径，却完全没有碰 `self._cache`。写后读的正确性**完全依赖 mtime 恰好变化**。

#### 实测复现（非静态推演）

构造长度恒定的目录内容，循环执行「`_save()` 写新内容 → `_load()` 读」，比对返回值与磁盘真实内容：

```
第2次: _load 返回 '房01'，磁盘实为 '房02'  ← 陈旧
第4次: _load 返回 '房03'，磁盘实为 '房04'  ← 陈旧
第6次: _load 返回 '房05'，磁盘实为 '房06'  ← 陈旧
...
共 30 次写后读，16 次读到陈旧数据
```

**16/30 的陈旧率**。

#### 影响

`DeviceCatalog` 是「自然语言设备名 → 真实 `entity_id`」的解析源，`resolve()` 的每一次调用都先 `_load()`。触发路径是「写入后很快再读」：

- `refresh()` 刷新目录后立刻 `resolve()`
- `set_alias()` / `remove_alias()` 写入别名后立刻 `resolve()`（这正是加别名后马上验证的工作流）

表现为**刚刷新的设备目录读不到、刚加的别名不生效**，且重启后神秘恢复——典型的「陈旧缓存掩盖真因」（第二轮报告里我记过同一形状）。

#### 与死代码的关系（本轮最值得记的一条）

DEAD-01 在本轮只命中**一处**：

```python
# af_catalog.py:303-315
def area_of(self, entity_id: str) -> str:
    ...
    if not meta:
        return ""
    return _meta_area(meta)
    self._cache = None        # ← 在 return 之后，永不执行
```

这行死代码**本身无害**（不执行 = 不影响功能），但它是决定性线索：`_cache = None` 恰好是 BUG-08 缺失的修复动作，而它被留在了 `area_of()` 的 `return` 之后。作者显然**有过**「写完要失效缓存」的意图，只是放错了位置、且从未生效。

**修复建议**：

```python
def _save(self, payload: dict[str, Any]) -> None:
    path = self.catalog_path
    path.parent.mkdir(parents=True, exist_ok=True)
    atomic_write_text(path, json.dumps(payload, ensure_ascii=False, indent=2))
    self._cache = None          # ← 写盘即失效（或直接用 payload 更新缓存）
```

同时删除 `area_of()` 末尾那行永远执行不到的 `self._cache = None`。

更彻底的做法是把缓存键换成 `(st_mtime_ns, st_size)` 或直接改用文件内容哈希——但**失效是最低成本且必然正确的修复**，改键只是降低碰撞概率。

### 本轮对整体判断的补充

前五轮我反复归结为「**失败语义不统一**」。BUG-08 提供了第三个同源样本，且是最清晰的一个：**写入路径与读取缓存之间没有契约**。至此，8 个缺陷可以按根因归成三类：

| 根因 | 缺陷 |
|---|---|
| **写入路径不统一**（有的走原子写、有的裸写；门禁只守半边） | BUG-03、BUG-05 |
| **失败语义不统一**（一个崩一个哑；一个降级一个致命） | BUG-03、BUG-04、BUG-07 |
| **缓存/状态失效不统一**（写盘不失效缓存；坏行不剔除） | BUG-04、BUG-08 |

三类都指向同一件事：**这个项目在单点上写得很好（原子写助手、环检测、状态机迁移表、`_Budget` 上限），但缺少把「正确写法」变成「唯一路径」的机制**。BUG-05 已经证明连门禁也只守住了半边。
