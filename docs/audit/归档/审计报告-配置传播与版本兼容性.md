## 三、确证缺陷

### 🟠 BUG-15（中危）`af_preference._migrate_legacy()` — try 只包住读取与解析，结构使用在其外

**位置**：`src/autoforge/af_preference.py:539-555`

```python
def _migrate_legacy(self) -> list[PreferenceRecord]:
    """旧整档格式（preferences.json）只读迁移：读入后由 `_rewrite_all` 落成 JSONL。
    不删除旧文件、不覆盖旧文件——迁移可逆。"""
    path = self._path(LEGACY_PREFERENCES_FILE)
    if not os.path.exists(path):
        return []
    try:
        with open(path, "r", encoding="utf-8") as f:
            data = json.load(f)
    except (OSError, json.JSONDecodeError):
        return []
    recs = [r for r in (self._record_from_row(row) for row in data.get("records", []) ...)  # ← try 外面
    self._min_samples = data.get("min_samples", self._min_samples)                          # ← try 外面
    ...
```

`try` 只覆盖了 `open()` + `json.load()`，**`data.get(...)` 的两处使用都在 try 之外**。

#### 实测复现

```
顶层 dict（完整旧档）   → 迁移成功，记录数 = 1（新档生成、旧档保留）
顶层 list（数组式旧档）  → AttributeError: 'list' object has no attribute 'get'
顶层 null              → AttributeError: 'NoneType' object has no attribute 'get'
顶层字符串              → AttributeError: 'str' object has no attribute 'get'
```

后三种情况下，`PreferenceModel(persist_dir=...)` **构造直接失败**——不是"迁移跳过"，而是整个偏好模型不可用。

#### 与 BUG-04 是同一形状

| | 位置 | try 覆盖 | 未覆盖 |
|---|---|---|---|
| BUG-04 | `af_metrics.flush_buffer` | 网络发送 | `json.loads(line)`（解析） |
| **BUG-15** | `af_preference._migrate_legacy` | `open()` + `json.load()` | `data.get()`（**结构使用**） |

两处都是**"try 只包了一半"**——包住了"拿到数据"，没包住"用数据"。而且 BUG-15 更隐蔽：`except (OSError, json.JSONDecodeError)` 看起来覆盖了读文件的全部风险，容易让人以为已经安全。

#### 触发条件

`preferences.json` 是**旧格式遗留文件**（新格式是 `preferences.jsonl`）。它可能被写坏的场景：截断写入留下 `null`、其他工具写成数组、手工编辑、跨版本残留。这类文件恰恰是"迁移"功能要处理的——**而处理它的代码自身没有兜底**。

#### 修复建议

```python
    try:
        with open(path, "r", encoding="utf-8") as f:
            data = json.load(f)
    except (OSError, json.JSONDecodeError):
        return []
    if not isinstance(data, dict):        # ← 补这一行
        return []
```

或把后续使用一并纳入 try。前者更明确（区分"读失败"与"格式不符"）。

## 四、正面结论：这几处配置处理做得正确

本轮专门验证了配置与版本兼容性，以下实现**经核验正确**，记录以免后续重复排查：

| 实现 | 位置 | 正确之处 |
|---|---|---|
| 预测模型版本校验 | `af_predict.py:864` | `payload.get("version") != MODEL_VERSION` → **隔离文件 + 冷启动 + 告警**。三个动作齐全，是版本不兼容处理的范例 |
| 场景状态加载 | `af_scene.py:274-277` | `isinstance(payload, dict)` + `isinstance(records, dict)` 双重结构校验，失败 fail-open **且带日志**（含路径） |
| env 覆盖配置 | `af_conflict_runtime.from_env` | `float()`/`int()` 转换全部包在 `try` 内，解析失败跳过——**与 BUG-10 的模块级裸解析形成对照** |
| 偏好记录反序列化 | `af_preference._record_from_row` | 未知键忽略、缺关键字段整行丢弃（`except (TypeError, ValueError): return None`） |
| 旧档迁移可逆性 | `af_preference._migrate_legacy` | 不删除、不覆盖旧文件（已实测确认：迁移后 `preferences.json` 仍在） |

**一个值得注意的对照**：`from_env` 的 env 解析有 try 保护且 fail-safe（正确），而 BUG-10 的 5 处**模块级** env 解析没有。同一个仓库里两种做法并存——又一次印证「正确写法存在，但没变成唯一路径」。

### 「try 只包一半」是本轮收敛出的新子类

把十三轮的异常相关缺陷按精确形状分组，会发现一个此前没单独拎出来的子类：

| 缺陷 | try 覆盖了 | 漏掉的 |
|---|---|---|
| BUG-04 | 网络发送 | **解析**（`json.loads` 在 try 外） |
| BUG-15 | 读取 + 解析 | **结构使用**（`data.get` 在 try 外） |
| BUG-13 | 主流程 | **降级路径**（记账函数内部无 try） |

三处的共同点：`except` 子句**看起来**覆盖了风险（`OSError`/`ValueError`/`Exception` 都写了），但保护范围比开发者以为的窄一截。这类问题读代码时极难发现——因为 `try` 就在那里。
