## 五、修复设计原则

本次 33 条修复贯穿以下统一原则：

1. **Fail-closed（安全面优先）**：读不出/形状不对时拒绝操作，不得用空值覆盖坏文件。AF13/AF49/AF66/AF67/AF79 均按此原则。
2. **区分"合法空态"与"损坏"**：文件不存在/0字节/纯空白 = 合法空态（放行初始化）；文件存在但读不出/解析失败/形状不对 = 损坏（拒写+留痕+隔离）。AF52/AF76/AF77 统一此口径。
3. **失败如实传播**：不得用 ok=True 掩盖失败。AF57（隔离失败）、AF58（PID写失败）、AF64（批量部分失败）均改为如实返回。
4. **批量单点失败不拖垮整体**：AF64（逐项成败）、AF71c（坏 sidecar 跳过不 500）、AF57（隔离失败留原地待重试）。
5. **日志留痕**：所有静默吞异常的分支均补 logger.warning/error，且尽量使用具名码（如 CONFIG_REVISION_UNREADABLE、CATALOG_VERSION_MISMATCH）。
6. **最小改动**：每条修复只改必要的代码，不重构无关逻辑。af_auth.py 中已有的 except_token 在途修改完整保留。
