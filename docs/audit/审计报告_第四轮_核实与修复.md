### 缺陷 2（报告判 低-中）：undo 各域恢复策略不一致 —— **属实，本轮已修**

实测复现（修复前，对 GitHub 当前代码跑的）：

```
light.x      {"state": "on", "attributes": {"brightness": "unknown"}}  -> ('light.turn_on', {'entity_id': 'light.x'})   # 静默丢字段
fan.x        {"state": "on", "attributes": {"percentage": "unknown"}}  -> ('fan.turn_on', {'entity_id': 'fan.x'})       # 同上
cover.x      {"state": "open", "attributes": {"current_position": "unknown"}} -> None                                  # 整块放弃
climate.x    {"state": "heat", "attributes": {"temperature": "unknown", "hvac_mode": "heat"}} -> None                   # 整块放弃
revert -> {'ok': True, 'restored': ['light.x'], 'failed': [], 'skipped': ['cover.y']}
```

报告只说了"三种策略不一致"。**同一根因下还有一条更危险的，报告没抓到**：

```
light.x   {"state": "unknown"}     -> ('light.turn_off', …)     # 状态"我不知道"被当成"关"
switch.x  {"state": "unavailable"} -> ('switch.turn_off', …)
lock.x    {"state": "unknown"}     -> ('lock.unlock', …)        # 对状态未知的锁下发解锁
```

`_OFF_STATES` 里塞了 `unknown`/`unavailable`，把 HA 的"读不出"哨兵当成了"关/合"。
`_lock` 又是 `if st in ("locked","true","1") … else unlock` —— 于是"读不出"直接落到**解锁**分支。
这已经不是"部分恢复"，是**依据不可读的状态对设备做一次不可逆写**。
另外 `_OFF_STATES` 之外的状态（`jammed`、`locking`、`standby`）走 `else "on"`，同样是猜。

## 二、修复内容

### 统一后的唯一恢复策略（`src/autoforge/af_undo.py`）

> **读得出的目标一定回放；读不出的字段一定如实上报；既不猜值，也不假装恢复完整。**

| 情况 | 六个域统一行为 |
|---|---|
| 状态缺失 / `unknown` / `unavailable` / 白名单外（`jammed`、`locking`、`standby`…） | `restore_call` → **None**，跳过整个实体，不写设备 |
| 恢复目标本身读不出（cover 的 `current_position`） | **None**（HA 的 `cover state=open` 覆盖 1%–99%，"全开"不是恢复，绝不下发 `open_cover`） |
| 方向读得出、附加属性读不出（`brightness`/`color_temp`/`percentage`/`temperature`） | 回放方向，字段进 `RestoreCall.gaps` + warn 日志 |
| 快照里本来就没有该字段 | **不算 gap**（没东西丢失） |

实现要点：

- 新增 `RestoreCall(NamedTuple)`：`action / params / gaps`。`gaps` 非空即"部分恢复"，调用方必须呈现。
- 新增 `_ILLEGIBLE_STATES = {unknown, unavailable, none, ""}`，从 `_OFF_STATES` 里**移出** `unknown`/`unavailable`。
- 新增 `_direction()`：`_OFF_STATES` / `_ON_STATES` **双向白名单**，白名单外返回 None（不再 `else "on"`）。
- 新增 `_num_attr(attrs, key, …, cast)`：返回 `(值, 是否算 gap)`，把原来 4 处
  `except (TypeError, ValueError): pass` 收口成"点名上报"；顺带拦 `nan`/`inf`
  （`float("nan")` 能通过 `float()`，送进 HA 会被 400 拒——与第三轮求值层收口同一口径）。
- `_lock` 改为走 `_direction`，`jammed`/`locking` 不再落到 `unlock`。
- `_climate`：温度读不出但 `hvac_mode` 读得出 → `set_hvac_mode` + `gaps=("temperature",)`（与 light 同策略，不再整块放弃）。
- `UndoStore.revert()` 返回值新增 **`partial`**（`{entity_id, action, not_restored, message}`）与
  **`fully_restored`**（`ok and not partial and not skipped`）——修掉"谎报全部恢复"。
- `af_canary.rollback()` 用 `call.action/call.params`，`gaps` 非空记 warn（部分恢复不静默）。
- `forge undo` CLI 打印 `· 部分恢复 <实体>：已下发 <动作>，快照里 x/y 读不出、未回放`（stderr）与 `· 恢复失败：[…]`。

### 反例锁（`tests/unit/test_undo_policy_unified.py`，30 项）

- 六域 × `unknown/unavailable/None/""` 状态 → 一律 None（不许下发写操作）；
- 四个方向域 × `jammed/locking/opening/cleaning/standby` → 一律 None；
- 六域 × 6 种"读不出"形态（`unknown`/`unavailable`/`"abc"`/`nan`/`"12x"`/`{}`/`[]`）
  → **要么 None，要么 `gaps` 点名该字段**，绝不允许"丢了字段却 `gaps==()`"；
- 字段缺失不算丢失（`gaps == ()`）；
- `params` 每个数值都能在快照里找到出处（不许默认值冒充）；
- `revert` 的 `ok=True` 但 `partial` 有内容、`fully_restored=False`；干净快照才 `fully_restored=True`；
- `DOMAIN_SETTER` 键集合钉死为 6 个域（新增域必须一并进上面的扫描）；
- setter 抛异常 → 仍 fail-closed 返回 None。

   单纯 fail-closed 会把"方向明明读得出"的实体整个放弃（灯不亮、空调不设回原模式），
   那是把不一致换成了另一种错；现在的口径是"能回的一定回，回不出的必须说"。
