### 证据1 af_evo 算法复杂度与边界 ###
=== [1] _balanced 分桶边界 ===
  _balanced(0项,3份) -> [[]]  总长=0
  _balanced(1项,3份) -> [[0]]  总长=1
  _balanced(5项,3份) -> [[0, 1], [2, 3], [4]]  总长=5
  _balanced(7项,0份) -> [[0, 1, 2, 3, 4, 5, 6]]  总长=7
  _balanced(5项,-1份) -> [[0, 1, 2, 3, 4]]  总长=5
  _balanced(0项,0份) -> [[]]  总长=0
  _balanced(3项,10份) -> [[0], [1], [2]]  总长=3

=== [2] _jaccard 空集/除零 ===
  jaccard(set(),set()) = 1.0
  jaccard({1},set()) = 0.0
  jaccard({1, 2},{2, 3}) = 0.3333333333333333
  jaccard({1},{1}) = 1.0

=== [3] _max_jaccard 空输入 ===
  _max_jaccard([],[]) = 0.0
  _max_jaccard([frozenset({1})],[]) = 0.0
  _max_jaccard([],[frozenset({1})]) = 0.0

=== [4] _max_jaccard 复杂度（O(n*m)?）===
  n= 100 x  100 ->     1.86 ms
  n= 400 x  400 ->    28.72 ms
  n= 800 x  800 ->   125.30 ms
  → 若耗时随 n² 增长则为 O(n*m) 全对比较

[5] 空集 Jaccard=1.0 的实际影响
==================================================================
  jaccard(∅,∅)=1.0 → 两个『无 token』的自动化被判为 100% 相似

  什么情况 trigger token 会为空？
    trigger=None -> tokens=set()  (空=True)
    trigger={} -> tokens=set()  (空=True)
    trigger={'type': 'state'} -> tokens={"type='state'"}  (空=False)
    trigger={'type': 'unknown_kind'} -> tokens={"type='unknown_kind'"}  (空=False)
    trigger={'entity_id': 'light.x'} -> tokens={"entity_id='light.x'"}  (空=False)

  两条自动化：一条无 trigger，一条也无 trigger → 相似 100%

  [6] _dedupe_triggers 是否受影响
    输入2个 -> 去重后1个
    输入2个 -> 去重后1个
    输入2个 -> 去重后2个

[7] _clamp / _clamp01 / _to_int / _to_float 边界
==================================================================
    _clamp(5, 10, 1) -> 10
    _clamp(5, 1, 10) -> 5
    _clamp01(-1,) -> 0.0
    _clamp01(2,) -> 1.0
    _clamp01(nan,) -> 1.0
    _to_int('5',) -> 5
    _to_int('abc',) -> None
    _to_int(None,) -> None
    _to_int(inf,) -> ❌ OverflowError: cannot convert float infinity to integer
    _to_float('1.5',) -> 1.5
    _to_float(nan,) -> nan
    _to_float(inf,) -> inf
