# 交接卡 · F12 预测性触发消费闭环

**日期**：2026-09-29
**决策**：band 策略 A（仅 auto 档自动提前写设备）；预触发服务经 `af_runtime_ext.ConfGrading.install` 挂入 runtime，周期 ~90s 扫描；`af_predict` 不 import `af_conf`，band + 经验先验由调用方注入。

## 改动文件

| 文件 | 性质 | 说明 |
|------|------|------|
| `src/autoforge/af_pretrigger.py` | **新建** | `TriggerHistory`（Predictor 的 history_store，记录真实触发）+ `PreTriggerService`（周期扫描 + band 闸门 + 经验先验注入）。纯新增，不修改任何现有文件。 |
| `src/autoforge/af_predict.py` | 改 | `Predictor.pre_trigger` 增加 `prior=None, prior_weight=None` 透传参数（零回归：缺省行为与旧版完全一致，旧单测全过）。 |

## 行为增量

- **消费闭环闭合**：`af_predict` 此前是纯新增模块，「消费闭环待 F12 预触发调用方接入」。本服务即调用方：周期（默认 90s）扫描 `runtime.graph` 全部自动化，对每个做 `learn → band 判定 → 预测 → 命中且 auto 档则 `pre_trigger`。
- **真实触发历史来源**：包裹 `runtime.instances.on_spawn`（每次自动化真正触发落点于此）把 `automation_id` 写入 `TriggerHistory`，再喂给 `Predictor.learn`。总线 `BusEvent` 是实体级事件、不带 `automation_id`、不支持通配订阅，故不采用。
- **band 策略 A（已决策）**：只有 `band == "auto"`（`conf >= 0.85`）才允许预测命中后自动提前写设备；`shadow` / `ask` 档命中后**永不自动写设备**（沿用 G4 闸门），仅计数 `skipped_band`。
- **经验先验注入点（F11②）**：`PreTriggerService.experience_prior_for(aid)` 从 `ExperienceStore.empirical_prior(实体集合, 适配器集合)` 取 `(mean, weight)` 注入 `predict / pre_trigger`。当前 `install` 传 `experience=None`（未接经验库），先验缺失即零回归。
- **持久化**：`TriggerHistory` 写 `<persist_dir>/pretrigger_history.json`，`Predictor` 写 `<persist_dir>/predictions.json`，二者同目录隔离、互不干扰；均 fail-open（写盘失败不影响运行）。
- **at-most-once**：`pre_trigger` 标记先落盘再触发，重启/重复扫描不会重复写设备（单测已验证）。

## 已知风险 / 待做

1. **`learn` 每扫描周期对全部自动化重拉全量历史并去重**（依赖 `seen` 集合幂等）。原型期自动化数量小可接受；规模变大后可改为增量 learn（按 last_scanned 时间窗）。
2. **`scan` 里预测与触发各算一次概率**（先 `explain` 判阈值，再 `pre_trigger` 内部重算）。数值一致，仅轻微重复开销；若要省一次计算，可让 `pre_trigger` 接收外部 `info` 直接触发（后续优化）。
3. **经验先验未接线**：`install` 传 `experience=None`。接入 `ExperienceStore`（需从 runtime 暴露）后即可启用 F11② 先验平滑；当前不接不影响正确性。
4. **生产部署**：`e:/NAS` 是断开副本，改动须 scp 到 NAS `/vol1/1000/docker/autoforge/src` 再重建/重启容器才对运行容器生效（与既有 AutoForge 部署流程一致）。
5. **`Predictor` 构造 persist_dir**：当 runtime 未设 `persist_dir` 时回退为 `"."`（当前目录写 `predictions.json`）；生产 runtime 均带 `persist_dir`，问题不触发。

## 合并影响

- 仅新增 + 小范围增强 `af_predict.pre_trigger`（向后兼容）、扩充 `af_runtime_ext.install`（G4 组装层，已在此处挂多模块，模式一致）。
- 不改动 `af_conf` / `af_predict` 的既有权衡与阈值口径；band 决策单一真值源仍是 `af_conf.decision_for`。
- 无新依赖（仅 stdlib）。
