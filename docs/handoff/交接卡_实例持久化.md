## 2. 行为增量（与上一里程碑的差异）

- `persist=true` 的自动化的**活跃/挂起**实例落盘；终态即删除。进程重启时（`run`/`watch`
  带 `--persist-dir`）**自动恢复**这些实例。
- **定时器跨进程**：落盘 `due_at_wall`（墙钟，因为 `monotonic()` 重启即归零、跨进程不可比），
  恢复时换算回新的 `monotonic()`；**崩溃期间已错过的超时**在恢复后首次 `tick()` 立即触发 `on_timeout`。
- **丢弃规则显式且可审计**：自动化不在当前图 / `persist` 已关 / 落盘状态为终态 → 删文件 +
  记 `instance_restore_dropped`，绝不静默保留。
- 恢复的实例**保持落盘时的状态**，快照按 IR §7.1 **重取**（`attach` 丢弃旧快照）。
- 对外契约（CLI）：`forge run --persist-dir <dir>`、`forge watch --persist-dir <dir>`。
- 无 IR Schema 破坏性改动；`persist` 字段本就存在（仅由"拦截"改为"生效"）。

  - 非 `persist` 不落盘；缺自动化丢弃 + 审计。

## 4. 已知风险 / 残留项

- [ ] **定时器进度是"落盘时刻快照"**：仅在状态迁移时落盘；`active` 实例若在两次迁移之间崩溃，
  最后落盘点是上次迁移（对 `wait`/`ask` 即挂起点，语义正确）。不影响主链路。
- [ ] **调度器内部状态未持久化**：`for` 持续条件的 pending、`queued` 队列、`time` 触发去重、
  总线熔断计数均为内存态，重启即清零（P1 后续话题）。
- [ ] **挂起 `ask` 的应答会话未重建**：恢复后挂起的 `ask` 实例仍在，但 `executor.pending_asks`
  不主动重建，人工应答需等下次 `tick`/重放（后续）。
- [ ] **单写者**：同一 `--persist-dir` 被多进程同时写会互相覆盖（无跨进程锁，P1 话题）。
- [ ] **TTL 依赖墙钟**：`created_monotonic` 由 `created_at` 墙钟回推，跨重启近似正确（墙钟不跳变时）。
