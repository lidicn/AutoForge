## 2. 行为增量（与上一版的差异）

**核心**：让失败**可归因、可复用、可喂生态**——纯规则、零 LLM、零侵入。

### 2.1 错误知识库（有序正则归因）
- `RULES` 顺序即优先级、**首个命中即返回**；`CATEGORY_ADVICE` 每个精确类别**必有专门建议**。
- **兜底口径**：网络/上游规则排在 IR 语义规则**之前**——宁可多归「网关/上游」，**不冤枉 agent**。
- 有界：JSONL 超出 500 条自动 `prune`（保留最近，原子重写）。

### 2.2 失败归因遥测（零侵入 `_telemetry`）
- `attach()` 只补一个下划线键，**不改** `ok`/`errors` 等既有字段、不改控制流。
- 形状：`{ok, category, label, advice, tokens, ts, history}`；失败时 `history` = 同类别最近 3 条（**写→读闭环**）。
- `TelemetryStore.usage()` 四维聚合（tool / category / ok / day）+ 总 token，30 天窗口。

### 2.3 实体共现经验（只在成功时更新）
- `pair = "|".join(sorted({a,b}))` —— `a|b`/`b|a` **合并**，不分裂计数；同实体不配对。
- **失败样本完全不进**（`observe(graph, ok=False)` 直接返回）；采集钩在 `save_graph` 成功落盘后。
- `export()` 出结构化 JSON（`pairs/entities/patterns`），与 v0.5.0 指标回灌形成**双向**。

### 2.4 失败回执附历史同类
- MCP `dispatch` 异常路径：`record_failure` + 在错误文本后追加 `↳ 归因：<label>｜建议：<advice>｜历史同类 N 条`（遥测失败不影响原错误）。
- `build` 的 `ok:false`：`_telemetry` 带 `category/advice/history`。

### 2.5 解析遥测五档 + 歧义消歧
- `resolve()` 出口归入 `exact/medium/low/ambiguous/none`（多 medium 且无明确 top → `ambiguous`），累加 `{root}/.catalog/resolve_metrics.json`（`FileLock` + 原子写，多进程不丢计数）。
- 候选不唯一时附 `disambiguation = {hint, candidates}`，`hint` 复用域契约（`possible_states`）与 v1.2.0 `Diagnostic.hint` 的「怎么改」语义。

## 3. 验证方式

```powershell
# 全量
python -m pytest tests -q
# 本版单测（29 条）
python -m pytest tests/unit/test_v1_5_*.py -q
# CLI 冒烟
forge experience show --root .forge
forge telemetry show --root .forge
```

- **归因**：`classify("连接 HA 超时")` → `UPSTREAM_HA`；`classify("… 不在白名单内（IR 未通过静态扫描）")` → `HTTP_NOT_WHITELISTED`（具体优先）；`KNOWN_CATEGORIES` 全部有建议。
- **有界**：记 600 条 → `recent(limit=1000)` 长 ≤ 500。
- **`_telemetry`**：`svc.build(BAD_IR, store=…)` → `_telemetry.category == "L3_ACTION"`，二次失败 `history` 非空；成功结果既有字段不变。
- **共现**：`observe(ok=True)` 两次 → `top_pairs() == [{"pair":"a|b","count":2}]`；`observe(ok=False)` 计数不变。
- **五档**：`resolve("客厅主灯")` → `exact`；`resolve("吊灯")` → `ambiguous` 且有 `disambiguation.hint`；`resolve("zzz")` → `none`；`resolve_metrics()` 漏斗累加且落盘。
- **接线**：MCP `af_experience`/`af_telemetry` 可调；HTTP 四端点 200；CLI 两命令 exit 0。

## 4. 已知风险 / 残留项

- [ ] **`simulate` 的 `ok` 恒 True**（失败以 `expect` 报告）：`_telemetry.ok` 反映**断言是否通过**，与 `result.ok` 语义不同——已在设计 §7.1 注明。
- [ ] **真实 runs/success 仅常驻进程有效**（既有事实，同 `get_metrics`）：CLI 一次性调用只落单条事件。
- [ ] **归因规则覆盖率**：`UNKNOWN` 会随时间补规则；`explain()` 的 `matched` 字段可用于统计未归类占比（未做自动告警）。
- [ ] **错误知识库/遥测为进程外文件**：多进程并发追加 JSONL 用 O_APPEND 单行不撕裂；`prune` 的重写窗口理论上可与追加竞争（量小可接受，未加锁）。
- [ ] **NAS 复核**：✅ 已完成（`/api/experience`、`/api/telemetry`、`/api/catalog/resolve-metrics` 均 200；失败归因端到端 → `by_category={"L3_ACTION":1}`、`knowledge={"L3_ACTION":1}`）。

## 5. 合并影响（merge-impact）

- **是否破坏既有 IR 样例**：否（未改 IR Schema）。
- **对外契约**：
  - `resolve()` 返回**新增** `bucket`（及歧义时 `disambiguation`）——附加字段，不破坏既有结构；
  - `svc.simulate` 新增**可选** `store=` 关键字参数——向后兼容；
  - 新增 4 个 read HTTP 端点、2 个只读 MCP 工具、2 个 CLI 子命令组——纯新增。
  - 副作用：`build`/`simulate` 会在返回 dict 里多一个 `_telemetry` 键（**下划线前缀，约定为遥测元数据**）。
- **对 MA 的影响**：`export_experience()` 成为新的事实回灌面（AF 采集事实 → MA 生成假设），与 v0.5.0 `MA_METRICS_CONTRACT.md` 并列；不影响既有指标契约。
- **部署**：纯 Python 改动 + 新增 3 模块；`src/autoforge/` 整体 `scp` 到 `/vol1/1000/docker/autoforge/src` 后 `docker restart autoforge-api` 即生效（容器挂源码卷，无需重建镜像）。新增落盘：`{root}/error_knowledge.jsonl`、`{root}/telemetry/usage.jsonl`、`{root}/experience.json`、`{root}/.catalog/resolve_metrics.json`。
