## 2. 行为增量（与 v0.2.0 的差异）

- **新增能力**：自动化可在节点上声明 `emit`，向事件总线**发布非实体自定义事件**，为 v0.4.0 的 `on event` 订阅铺路。
- **关键设计决策**：`emit` 采用**节点字段**形态，**不新增第 8 种 `kind`**——
  依据：schema 中 `kind` 为封闭枚举且 `emit` 本就是 object 字段；`IR_AND_RUNTIME.md` §5 明确"7 种节点"；
  `persist` 已有"字段而非 kind"的成功先例。改动面最小且不触碰 7 节点铁律。
- **通道隔离**：自定义事件走独立通道（主体 `event.<name>`、`source="emit"`、无 `last_changed`），
  与实体状态事件**共享**去重/节流/熔断结构，但 `dedup_key` 含 `event_id`，因此**每次发布都是新事件**。
- **延迟发布**：`delay` 走实例定时器（`kind="emit"`）+ `TimeSource`，`tick()` 到点后发布并按 `then` 继续（**不是** `on_timeout`）。
- **编译期检查**：
  - `EMIT_SELF_LOOP`（ERROR）：A emit `x` 且某自动化由 `event.x` 触发 → 成环（含自环）。
  - `EMIT_STORM_LIMIT`（WARNING）：emit 节点数 > 3，或同一事件名被重复 emit。
- **运行期保护**：事件风暴由**总线熔断**兜底；被限流/熔断**只落审计、不进 `on_error`**（系统保护 ≠ 逻辑失败）。
- **对外契约**：
  - IR Schema：`emit` 字段正式化（向后兼容——旧图无 emit 不受影响）。
  - AF-Spec：`emit {...}` 无损往返。
  - HTTP：新增审计类型 `event_emitted`（出现在 `/api/sim` 与 `/api/graphs/{name}` 的审计里）；无新端点。
  - CLI：无新增子命令。

## 4. 已知风险 / 残留项

- [ ] **订阅侧未实现**：`on event` 属 v0.4.0。当前自定义事件**没有订阅者**，其"被消费"的能力未被验证；
  已有 `BusEvent.event_name()` 与总线精确订阅（按 `event.<name>`）作为对接点。
- [ ] **emit 挂 `pass` 节点时**：进入节点先广播再终止（语义"发出后结束"）；挂 `do`/`set` 等节点时，
  事件在节点主逻辑**之前**发布（"发出事件后继续做"）。若未来需要"动作成功后再发"，需再讨论顺序语义。
- [ ] **风暴阈值沿用实体熔断参数**（5 次/10s、冷却 30s），未按事件通道独立配置；若后续事件频度远高于状态变更，需要单独调参。
- [ ] **节流 200ms 对事件通道偏保守**：高频 emit 场景易被节流（测试里需主动推进时钟）。
- **影响范围**：以上均为语义/参数层面的待优化，**不影响生产 Runtime 主链路**，也不破坏既有行为。
