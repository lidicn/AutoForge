## 2. 行为增量（与 v0.1.0 的差异）

- **新增能力**：真 vhass 路径首次覆盖**适配器层故障**（`timeout` / `drop` / `fail` / `unavailable`）——此前 `HassAdapter` 未接 `FaultQueue`，vhass 只覆盖状态层 / 事件层故障。
- **接口增量**：`GET /api/diff` 响应新增 `notes: {old, new}`（两版**归档备注**）。
- **前端**：置信度页查询口径统一为 `_all`；版本 Diff 页展示两版备注，消除"内容无差异"的困惑。
- **编译期 / 运行期闸门变化**：无（本版不改 IR Schema 与 `af_scanner`）。
- **对外契约（CLI / IR Schema / 常量）**：
  - 无新增 CLI 子命令；IR Schema 零改动；阈值常量未动。
  - HTTP 契约：`/api/diff` **新增字段**（向后兼容增量项，老前端忽略即可）。

## 4. 已知风险 / 残留项

- [x] **NAS 镜像缺 `fastapi`**：镜像构建早于依赖补齐，导致 `test_af_api.py` 经 `pytest.importorskip("fastapi")` **整模块 skip**（少收集 24 条 → 恰好解释 235 − 211 的差额）。已 `docker build` 重建修复。
  → **后续凡 `pyproject.toml` 依赖变更，必须重建该测试镜像**。
- [ ] **前端 `build.emptyOutDir = false`**：受限环境会把 node 的 `fs.rmSync` 重定向到"安全删除"并在清空 `outDir` 时失败（`prepareOutDir → emptyDir` 报错），故关闭自清空。副作用：`dist` 会**累积旧产物**（文件名带 hash，无功能影响）；部署环节暂未做清理。
- [ ] **NAS 应用容器需重启才加载新代码**：`af_service.py` 等改动同步后，须 `docker restart autoforge-api`（Python 进程已加载旧模块）。
- [ ] 部署挂载目录时**必须原地覆盖文件**，不可 `mv` 替换目录（会使容器 bind mount inode 失效 → 500）。
- **影响范围**：以上均为**构建/部署环境**问题，**不影响生产 Runtime 主链路**。
