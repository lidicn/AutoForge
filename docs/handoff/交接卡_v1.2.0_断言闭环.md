> 动机：AutoForge 的 IR **没有任何期望值字段**，`af_simulate` 只返回 `final_states`——
> **跑完了，但没人说「应该是什么」**。`forge build` 拦住了「不安全」，`forge sim` **没拦住「逻辑对但语义错」**。
> 前身 autoflow 的 DSL 强制写 `预期:` 块，`validate_intent` 把 `expected_postconditions` 列为硬性必填——
> 「没有成功判据就无法判定 flow 是否跑通」。

## 2. 行为增量（与上一版的差异）

**核心**：`forge sim` 从此能回答「跑**对**了吗」，而不只是「跑完了吗」。

**新增 IR 字段（唯一真相，已同步 JSON Schema）**：

```jsonc
"expect": [
  { "entity_id": "light.study_main", "state": "on" },              // 实体形态（state 可为候选数组）
  { "var": "turn_on_result.success", "op": "eq", "value": true }     // 变量形态（op 缺省 eq）
]
```

**`simulate()` 返回新增 `expect` 报告**：

| 字段 | 含义 |
|---|---|
| `ok` | 没有断言失败（只代表「没抓到反例」） |
| `fully_verified` | **比 `ok` 更严**：声明过断言且**全部验过**（无 fail、无 unverified、无未建模动作） |
| `declared` / `passed` / `failed` / `unverified` | 四计数 |
| `unmodeled_actions` | 仿真底座未建模的动作（其后果根本没被验证过） |
| `items[].status` | `pass` / `fail` / **`unverified`**（三者严格分开） |

**新增扫描检查**：

| 码 | 级别 | 拦什么 |
|---|---|---|
| `EXPECT_MISSING` | warning | 没声明 `expect` → sim 只能确认「跑完了」。**刻意用 warning**：不破坏既有 13 份样例 |
| `EXPECT_UNREACHABLE` | error | 断言的实体不在本图 `reads ∪ writes` → 该断言永远验不到 |
| `EXPECT_STATE_INVALID` | warning | 期望状态不属于该域契约（如灯断言成 `open`）；占位符域（`select`/`number`/`sensor`）跳过不误报 |

**诊断可行动**：`Diagnostic` 新增 `hint`，未显式给值时从 `CODE_HINT`（35 条）自动补；
`af_build` 的 `diagnostics[]` 带 `hint`，CLI 文本渲染为 `↳ 建议：…`。

## 3. 验证方式

```powershell
# 全量
python -m pytest tests -q
# 本版单测（22 条）
python -m pytest tests/unit/test_v1_2_expect.py -q

# 冒烟：新样例通过安全闸且 NL 渲染出「预期」段
forge build examples/ir/case11_expect.json
# 冒烟：既有样例出现带建议的告警（证明不拦截、只提醒）
forge build examples/ir/case01_day_light.json --no-nl
```

- 端到端：`simulate(case11, events=[motion on])` → `expect.ok=true` 且 `fully_verified=true`（`test_simulate_expect_passes_on_case11`）；
  把期望改成 `off` → `ok=false`（`test_simulate_expect_fails_when_wrong`）。
- 无事件时：实体已被播种（默认 `off`）而断言 `on` → **判失败**，不是用 unverified 掩盖「自动化根本没执行」（`test_simulate_without_events_still_fails_assertion`）。
- 样例体检仍 14/14：`python scripts/gen_schema_check.py`。

## 4. 已知风险 / 残留项

- [ ] **变量形态依赖实例 `vars`**：断言在「任一实例满足」时通过；多实例下语义偏宽松（无法确定是哪一个实例命中）。影响范围：仅报告精度，不影响 Runtime 主链路。
- [ ] **`EXPECT_MISSING` 是全量告警**：所有未声明 `expect` 的自动化都会报一条 warning。若后续觉得噪声大，可改为「仅当存在 `do` 写设备时才告警」。
- [ ] **vhass 未建模动作尚无自动降级到断言**：`VhassHarness.unverified` 已暴露，但**真 vhass 路径**尚未把 `unmodeled` 传给 `evaluate_graph_expects`（FakeHA 路径已接）。建议 v1.3.0 补齐。
- [ ] **NAS 容器复核未执行**：断开副本，需 scp + restart。
- [ ] `docs/API_CONTRACT.md` 未同步 `expect` 字段（权威形态以 `GET /openapi.json` 为准）。
