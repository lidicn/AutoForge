# 交接卡：AF MCP 面异常路径改 JSON 信封 —— 给 DB 的读数变化说明

| 项 | 值 |
|---|---|
| 里程碑 | 裁定 20261007 `20261007-DB凭据与AF降级面-裁定.md` §二 **戊A** 的 AF 半边 |
| 完成日期 | 2026-10-08 |
| 状态 | ✅ 已交付（AF 仓内判据已绿；对端读数口径见 §3） |
| 影响面 | **只影响 MCP 面**（`forge mcp` / `POST /mcp`）的工具返回文本；HTTP `/api/*` 面未改 |

---

## 1. 变了什么（一句话）

MCP 工具的**失败返回**从"一段散文"改成"一段 JSON 信封"。前缀字面量本身没动，
动的是**判别点**：DB 侧原先对整段文本做 `startswith`，现在必须先 `json.loads`，再对
`message` 字段做 `startswith`。

判别点不挪的后果不是报错，是**静默失效**——`{"ok": false, …` 永远不匹配
`READONLY_DEGRADED:`，降级态会被读成"没降级"。这正是本仓反复判红的那一族。

## 2. 前后形状对照（本机实测，非推导）

同一场景：生产 `forge serve` 正持有单写者租约，Agent 走 `af_live_run` 请求真机下发。

改之前（散文）：

```
READONLY_DEGRADED: 生产 serve 正持有单写者租约（<store_root>）：本次真机下发拒收。……
```

改之后（JSON 信封，实测输出，路径按本机临时目录原样）：

```json
{"ok": false, "code": "ADM_ERR_INTERNAL", "message": "READONLY_DEGRADED: 生产 serve 正持有单写者租约（C:\\Users\\lidicn\\AppData\\Local\\Temp\\…）：本次真机下发拒收。同一个 store 根目录上 HTTP 面已降级只读，MCP 面不抢锁、只读它（裁定 20261004 §一 1 A）"}
```

信封固定三键：`ok`（恒 `false`）、`code`（契约 §7.2 的 ADM 码）、`message`（给人读的那句，
`READONLY_DEGRADED:` / `PAIRING_PAUSED:` 这类机器前缀落在这里）。
`isError` 仍为 `true`（MCP 协议层没变），载荷在 `content[0].text`。

## 3. DB 侧要改的那一行

```python
# 旧口径（戊A 之前）
if text.startswith("READONLY_DEGRADED:"): ...

# 新口径
import json
try:
    payload = json.loads(text)
except ValueError:
    payload = None            # 老版 AF 的散文仍可能出现在旧镜像里
if payload and payload.get("ok") is False:
    msg = payload.get("message", "")
    code = payload.get("code")
    if msg.startswith("READONLY_DEGRADED:"): ...   # 单写者租约被占 ⇒ 降级只读
```

分档建议改按 `code` 判（比前缀稳，前缀是给"这一类拒绝"留的人类可读标记，不是枚举）：

| `code`（唯一真源 `homesdk.adm.errors`） | 含义 | 对端该做什么 |
|---|---|---|
| `ADM_ERR_PAYLOAD_INVALID` | 工具名未知 / 传了未声明的参数 | 修调用方，别重试 |
| `ADM_ERR_AUTH_REQUIRED` | MCP 面没有令牌身份，或缺该工具要求的 scope（裁定 20261004 §一 Q2=B 默认拒绝） | 配 `AUTOFORGE_MCP_TOKEN`，别硬试 |
| `ADM_ERR_INTERNAL` | AF 自己的业务拒绝（含 `READONLY_DEGRADED:` 那一族、只读服务层、接线缺口） | 按 `message` 前缀二次判别 |

> 兼容窗口：新 AF + 旧 DB 口径 = 降级态读成"没降级"（静默）。旧 AF + 新 DB 口径 =
> `json.loads` 抛 ⇒ 走 `except` 分支仍能按散文判。**所以推送顺序应当是先升 DB 判别、
> 再升 AF**；若反序，请把 §4 那条判据当作临时的降级报警来用。

## 4. AF 侧当场钉住这条口径的判据

- `tests/unit/test_serve_lease_single_writer.py::test_mcp_face_text_starts_with_the_prefix`
  —— 断言整段是 JSON、`ok is false`、`code == ADM_ERR_INTERNAL`、`message.startswith(PREFIX)`；
- `tests/unit/test_dcd_20261007_mcp_failure_envelope.py` —— 四类拒绝路径（未知工具、未声明参数、
  无令牌身份、缺 scope）逐条判形状与码。

复现：

```bash
GATES_PYTHON=<本机带依赖的 python> bash gates.sh
<同一枚 python> -m pytest -q tests/unit/test_serve_lease_single_writer.py tests/unit/test_dcd_20261007_mcp_failure_envelope.py
```

## 5. 本轮 AF 未做的事（别在对端等）

- HTTP `/api/*` 的错误体仍是 FastAPI 的 `{"detail": …}`，**没有**改成 `{ok, code, message}`；
  两面对不上这一点已投 DCD（`关键决策部/inbox/` 那份"降级面契约缺口四格"里的第 ⑤ 格）。
  用户端 UI 现在读 `body.detail || body.error || body.message`，所以 AF 单方面改键名会让它退化。
- `af/automation/failed` 载荷里的 `code` 格要等契约 v2.1（裁定 乙A）落地，AF 侧不预填。
