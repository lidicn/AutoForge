## 一、service_token 切换（DCD Q5 + 路线图 3.3.4）

### 背景

MA 已按 DCD 裁定完成 token 体系合并：
- 新增 `service_tokens.py`（`svc_` 前缀、sha256 落盘、常量时间比对）
- 30 天双轨期：旧 `BUTLER_TOKEN`（env 导入）仍可用，新 `svc_` 令牌并行
- 旧令牌使用量监控端点：`GET /api/config/service-tokens/legacy-usage`
- 下线条件：旧令牌连续 7 天使用量为 0 可吊销

### AF 侧现状

AF 通过 `POST /api/metrics/ingest` 回灌运行指标（`src/autoforge/af_metrics.py:188`），
认证方式为 `Authorization: Bearer {token}`，token 来源：
- CLI 参数 `--token`（`af_cli.py:1075`）
- 环境变量 `BUTLER_TOKEN`（`af_cli.py:1082`）

该端点在 MA 的 `BUTLER_SCOPES` 白名单中（`service_tokens.py:67`），需要 butler 作用域令牌。

### AF 侧需做

1. **申请新 service_token**：联系 MA 侧签发 AF 实例专属令牌（一实例一令牌，DCD Q3=A）
2. **切换认证**：将 `BUTLER_TOKEN` 环境变量替换为新 `svc_` 令牌
   - 临时方式：`export BUTLER_TOKEN=svc_xxx`（兼容现有代码，无需改源码）
   - 长期方式：新增 `AF_MA_TOKEN` 环境变量，代码优先读新变量
3. **验证**：切换后运行 `af metrics-push` 应返回 `{"ok": true, "dedupe_key": "..."}`
4. **观察期**：切换后观察 7 天，确认旧令牌使用量降为 0
5. **通知 MA 下线**：确认旧令牌 7 天零使用后，通知 MA 吊销 `butler-env` 记录

### 注意

- 旧 `BUTLER_TOKEN` 是 env 导入的只读记录，不落盘、不可在 MA 侧吊销
- 新令牌带 `token_kind` 字段，MA 日志区分 `service` / `legacy`
- 双轨到期日由 SP 定，代码不写死
- 端点路径与请求结构不变，仅 token 值变化
