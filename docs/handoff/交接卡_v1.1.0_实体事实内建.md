## 2. 行为增量（与上一版的差异）

**新增能力**：平台**自身**能回答「这个中文设备名对应哪个 entity_id」，Agent 不再需要绕道 MA。

```
之前：用户说人话 → Agent →(跨服务/跨鉴权)→ MA 取 ID → 回来写 IR
现在：用户说人话 → Agent 调 af_resolve_entity → 写 IR → build → sim → save   （同一 MCP 内闭环）
```

对外契约变化：

| 面 | 新增 |
|---|---|
| MCP 工具（5，均只读） | `af_refresh_catalog` / `af_resolve_entity` / `af_list_entities` / `af_get_entity_state` / `af_catalog` |
| HTTP 端点（5） | `GET /api/catalog`、`POST /api/catalog/refresh`（**写端点**）、`GET /api/entities/resolve`、`GET /api/entities`、`GET /api/entities/{id}/state` |
| CLI（5 子命令） | `forge entities refresh｜summary｜list｜resolve｜state` |
| 环境变量 | `AUTOFORGE_HA_TIMEOUT`（传输层超时，默认 10s）；复用既有 `AUTOFORGE_HA_URL` / `AUTOFORGE_HA_TOKEN` |
| IR Schema | **未改动**（本次不碰 IR） |
| 共享阈值常量 | **未改动**（`AUTO_MIN` / `SHADOW_LOW` 等不动） |

**关键设计约束（来自调研，已落地）**：
- **不过滤域**：同名设备可能对应 `light` / `switch` / `cover`，全部返回，由 Agent 看 `domain + friendly_name` 判断；
- **绝不静默猜域**：`resolve_best()` 只在无歧义（唯一候选 / top 置信度=high）时采纳，有歧义返回 `None`；
- **area 是提示不是硬约束**：解析不到即放宽全局并显式 `area_warning`；
- **防 DoS 三纪律**：`entity_id` 形态字符串不做模糊扫描；目录读带 `(mtime,size)` 缓存；列表强制分页（上限 200）+ `truncated` / `next_offset` 透明回报。

## 3. 验证方式

```powershell
# 全量
python -m pytest tests -q
# 本版单测（27 条）
python -m pytest tests/unit/test_v1_1_catalog.py -q

# 手工冒烟（需真实 HA 令牌）
$env:AUTOFORGE_HA_TOKEN = "<token>"
forge entities refresh --root .forge
forge entities resolve "书房吊灯" --root .forge
forge entities list --domain light --root .forge
forge entities state light.study_main --root .forge
```

- 关键验收：**目录为空时 `af_build` 静默退化为不校验**（`entity_check="skipped"`），
  绝不把「没刷过目录」误判成「实体全不存在」——`test_build_degrades_when_catalog_empty` 锁死。
- 解析四档置信度（entity_id 精确 / friendly_name 精确 / 子串 / entity_id 子串）逐档有单测。
- 样例体检仍 14/14：`python scripts/gen_schema_check.py`。

## 4. 已知风险 / 残留项

- [ ] **区域（area）维度不完整**：HA REST `/api/states` **不暴露 area 注册表**，本版只能从实体 attributes 的 `area` / `area_name` 取；取不到即 `area_warning` + 放宽全局。
      精确房间维度需 websocket 注册表（`config/entity_registry/list`），会引入 `websockets` 依赖、与「内核零依赖」冲突，**暂不做**——
      当前由 MA 的 `IdentityReconciler` 承担更合适。影响范围：仅解析精度，不影响 Runtime 主链路。
- [ ] **目录需手动刷新**：HA 设备增减后不会自动同步；`refresh` 是显式操作（与 autoflow 同策略，避免静默网络调用）。
- [ ] **NAS 容器复核未执行**：`E:\NAS\AutoForge` 与 NAS 已断开（`net use e:` 报连接不存在），需 scp 后重启容器再验。
- [ ] 未实现别名表（`entity_mapping`）：当前仅支持 friendly_name / entity_id 匹配；别名需求出现后再补。

- **是否破坏既有 IR 样例**：否。本次**不碰 IR Schema**，`examples/ir/*.json` 全部仍通过 `forge build`（样例体检 14/14）。
