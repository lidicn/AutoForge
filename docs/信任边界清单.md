# AF HTTP 信任边界清单（端点 × 方法 × 档位 × 网络前提）

第六轮审计 ARCH-05 的产物：报告说「缺『信任边界清单』这份可核对的资产——哪些端点匿名、哪些要什么 scope、
各自的网络前提是什么。当前这些信息分散在 60 多个路由装饰器里」，建议「从 `build_app()` 的路由表生成一份
清单并对打进 CI（形状检查：新端点必须显式声明 scope，默认拒绝）」。这份文件就是那份资产，
由 `scripts/check_trust_boundary.py` 每批判、`--write` 重新生成第一段表格。

## 一、口径（读之前先看这四条，否则会误读表）

- **真源只有一个**：`af_api.build_app(store_root=<临时目录>)` 构造出来的**运行期路由表**。不是
  `grep -c '@app\.'` 的条数——装饰器条数把条件注册算成无条件，而 scope 藏在 `requires(scope)` 返回的
  闭包自由变量里，静态文本读不出来。
- **档位怎么定的**：取每条路由 `dependant.dependencies` 的**顶层**依赖。带 `requires(X)` 闭包（读
  `scope` 自由变量）⇒ `scope:X`；只有 `authenticated()` ⇒ `optional`（带令牌就认、不带返回 None，
  由端点自己决定 401 还是继续）；只有安全方案实例（`security:HTTPBearer`，即令牌在处理器签名里）⇒
  `bearer-in-handler`；
  什么都没有 ⇒ `anon`。**`_readonly_guard` 不是鉴权**——它判的是单写者租约（只读降级实例拒绝写），
  所以四条 `POST /api/build`、`/api/bind`、`/api/sim`、`/api/spec/compile` 落在 `anon` 档，
  这是本门刻意要露出来的形状（安全第三轮 F-10「看起来设了权限」同一族）。
- **每条路由都额外带 `_rate_limit_dep`**（装配期挂在 `FastAPI(dependencies=…)` 上，全局生效）。
  它只做 IP/主体限速，**不鉴权**，所以不在表里逐条重复列。
- **射程边界（两格，明写不静默）**：① 装配不带 `ui_dir`，所以静态资源与 SPA 兜底 `GET /{full_path:path}`
  不进这张表（CI 的门禁作业没有前端构建产物；那两条面不承载 scope 语义）；② `HEAD`/`OPTIONS` 从方法列
  里剥掉，FastAPI 自动加的那对不算独立端点。
- **本门判什么、不判什么**：判"差有没有被认领"（新匿名面不登记就红、登记的理由指不到仓内真实记录就红、
  过期登记不删就红、安装器被接线就红）；**不判"该不该匿名"**——那是部署与安全口径，归 DCD，
  AF 不在这张表里替 owner 选口径。
