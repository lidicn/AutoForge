> 日期：2026-09-15｜规模：M｜依赖：—｜状态：✅ 已交付（本机 + NAS 双环境全绿，真机闭环验证通过）

## 一、交付要点

把 AF 的执行结果（执行次数 / 成功率 / 审计分布 / 置信度变化）回流 memory-agent，
形成"假设 → 验证 → 校准"闭环。AutoForge 侧产出**指标聚合 + 回灌客户端**，
MA 侧按契约加**最小接收端点**，闭环真实打通。

## 三、行为增量

1. **执行计数**：每个自动化 now 累计 `runs/success/failed`（实例 spawn→runs+1，done→success+1，fail→failed+1）。
2. **指标快照**：`MetricsAggregator(runtime).snapshot()` 输出 `{overall, automations}`，含成功率、审计分布、置信度带（auto/shadow/ask）。
3. **回灌客户端**：`Ingester.push()` 逐条 POST 到 MA，失败按 2ⁿ 秒退避（封顶 30s，默认 5 次），仍失败落 `metrics_buffer.jsonl`；`flush_buffer()` 重发（成功即删、失败保留）→ 断网不丢、恢复续传。
4. **接口**：`GET /api/metrics` 读端点；`forge metrics show <ir>` 本地预览；`forge metrics push <ir> [--events] [--ma-url] [--token] [--dry-run]` 推送。

## 五、已知风险 / 注意事项

- **exec/audit 维度需常驻进程**：原型期服务层无状态（每次请求建临时 runtime），`get_metrics(store)`（API 用）仅以持久化置信度为真实源，runs/success/failed 暂置 0/空。要让 API 反映真实执行计数，需引入常驻 runtime（`forge serve`/`watch`），本版本未做（留待架构加固）。CLI `push` 走本地 runtime + 可选回放，已能产出真实 runs。
- **MA 侧落盘路径**：`/data/af_metrics.json`（MA 容器挂载卷，重启保留）。若 MA 容器 data 卷未挂 `/data`，需调整 `app.py` 的 `DATA_DIR` 环境变量。
- **去重粒度=小时**：`dedupe_key = {automation_id}:{YYYY-MM-DDTHH}`，MA 端同 key 覆盖合并。高频重复推送不会放大。
- **退避在单测用 `max_retries=1`** 跳过 sleep，避免慢测试；生产默认 5 次。
