## 一、口径（先说清本门判什么、不判什么）

1. **判据的射程是 git 索引（入库面），不是磁盘。** 盘上一枚 `_tmp_probe.py` 不违反任何约定——`.gitignore:91`
   早就把它挡在库外了（这一格是 ARCH-08 复测里"成立·已有防线"那一行）。真正的洞是**入库面**：
   `git add -f` 能穿过 ignore，而"根目录躺着一份已入库的一次性脚本"ignore 根本管不着。所以本门读索引，
   git 读不出索引就是 `exit 2`（不许用"盘上没有"冒充"库里没有"）。同一口径的先例是
   `scripts/check_pkg_markers.py`（§二之四十四 实测：判磁盘会漏掉"盘上有、索引里没有"那一半）。
2. **一次性脚本的落点是 `scripts/oneshot/`。** 会被复用、有判据、进 CI 的脚本仍留在 `scripts/`（现读 38 份）。
3. **文件名 ⛔ 不带前导单下划线**（`_foo.py`）。`_*.py` 那条 ignore 没有前导斜杠，gitignore 语义下它在**任何深度**
   都匹配，所以 `scripts/oneshot/_foo.py` 同样进不了库；而双下划线的包标记（`__init__.py`）是本门刻意排除的另一族
   （`_` ＋ `*` 恰好吃掉 `__init__`，`.gitignore:94-98` 那段注释就是这次事故的记录，`!**/__init__.py` 是它的例外）。
   判据 B 因此只拦**单**下划线名，判据 D 反过来钉住那条例外没被人删掉——两头的漂移都能判红。
4. **本门不判"内容对不对"。** 那 4 份存量脚本里写着 `D:\Documents\...`、`/data/pending`、`/tmp/test_ir.json`
   这类仓外绝对路径，属"这脚本还能不能用"的问题，不属"该放哪"的问题；本门只把位置与命名钉成可 diff 的登记。
