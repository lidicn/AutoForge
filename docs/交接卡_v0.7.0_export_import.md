## 2. 行为增量（与 v0.6.0 的差异）

- 新增能力：**可携带的 store bundle 导出与备份恢复**。整个归档目录（每个名字的全部版本 + tags + 置信度快照）序列化为单一自描述 JSON bundle；导入时整库或按冲突策略恢复。
- bundle 形态：`{"format":"autoforge-bundle","version":1,"exported_at":...,"checksum":<sha256>,"entries":[...],"confs":[...]}`。
- **完整性保护**：`checksum` = 对规范化（sort_keys、排除 checksum 字段）的 entries/confs 做 SHA256；导入时复算并比对，损坏即拒（`ValueError`）。
- **导入前校验**：每个版本经 IR Schema 校验（`validate_automation`），不通过记入 `report["errors"]` 且**不落地**，不影响其他合法版本导入。
- **冲突策略**（目标 store 已存在同名归档时）：
  - `skip`（默认，最安全）：跳过整个冲突归档；
  - `overwrite`：先删已存在归档（版本目录 + conf 文件 + tags 侧车），再导入，版本号重置为原 v1…；
  - `rename`：导入到 `name_import` / `name_import2` … 新名字。
- raw 级一致：导入直接写原始 graph dict（`save_version_raw`），不经 Graph round-trip，保证导出→清空→导入后逐版本 graph 与 tags 完全一致。
- 对外契约：
  - CLI：`forge store export [--out <file>] [--root <dir>]`、`forge store import <file> [--strategy skip|overwrite|rename] [--root <dir>]`；
  - API：`GET /api/store/export`（读）、`POST /api/store/import {"bundle", "strategy"}`（写，受 API 令牌鉴权）；
  - 无新增 IR 字段、无修改既有 Schema、无改动共享阈值常量。

## 4. 已知风险 / 残留项

- [x] 风险1：bundle 为内存 JSON，超大 store（数百版本）可能占内存偏高；原型期可接受，未做流式。缓解：仅归档真机模板，量级小。
- [x] 残留：前端导入入口（Autoforge-UI 独立仓库）未随本版，后端契约已就绪，标记为 🔮，待 UI 迭代接入。
- [x] 残留：导出未含实例快照（`instances/*.json`，属 P1 运行时态，非模板资产），符合"模板导出"定位。
- [ ] 不影响生产 Runtime 主链路：导出/导入纯文件操作，不触碰 EventBus / Scheduler / Adapter，零运行时侵入。
