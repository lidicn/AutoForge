## 〇、版本号映射表（DCD 20261001·G，方案 A：双轨显式映射）

AutoForge 存在两套**并行且都正确**的版本口径，本表钉死映射，避免"对外说 v2.5、健康检查返回 0.1.0"的歧义：

| 包版本 / API 版本（机器契约） | 对外里程碑版本（人读叙事） | G 序号（af_service.MILESTONES） | 说明 |
|---|---|---|---|
| `0.1.0`（`pyproject.toml:7` / `af_service.API_VERSION`） | `v2.x`（当前 **v2.5 进行中**） | G1–G7 + 真机接线 | `/api/health.version` 返回 `0.1.0` 是**包/API 契约**，非里程碑；改它属发版动作（DCD 驳回，见裁定 G） |

> **发版纪律**：里程碑推进用 commit message 标签表达（如 `feat(v2.5/F6)`）；`pyproject` 与 `API_VERSION` **保持 `0.1.0` 不动**。
> **批次 ≠ 归版**：commit 前缀里的 `v2.5` 是该功能的**交付批次标签**；功能卡**归版**仍以路线图 §二 为准。F6 依 DCD 裁定归 **v2.5 过渡轮**（`883ac33` 事实），版本计划旧记「v2.2」为错记。

## 四、v2.3 需求决策门（已由 DCD 细案 §7 补全）
- `independent_multi`（实体集不相交、无依赖）：批量下发小功能即可，**不触发** group 排期。
- `dependent_multi`（实体集相交或有时序词）：才需复合编排；**门槛只看 `dependent_multi%` ≥5%**。
- 打点：`compose_intent` 落 `af_orchestrator.compose()` 后；看板 `compose_total` / `independent_multi%` / `dependent_multi%`；`dependent_multi%` 连续两周 ≥5% 提醒 DCD 评审。
