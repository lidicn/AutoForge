# `scripts/oneshot/` —— 一次性脚本的落点

约定与判据的正式口径在 [`../../docs/仓库卫生清单.md`](../../docs/仓库卫生清单.md)，由
[`../check_oneshot_layout.py`](../check_oneshot_layout.py) 每批对撞。这里只留操作说明。

## 什么时候放这里

手工跑一次就完的脚本：临时清场、一次性导出、跑批后人工分类、现场修补的备份件。
**会被复用、有判据、要进 CI 的脚本不放这里**，放 `scripts/`（那一边是门禁与验收件的口径）。

## 命名两条

1. ⛔ 不要前导单下划线（`_probe.py`）。`.gitignore` 的 `_*.py`／`_*.sh`／`_*.conf` 没有前导斜杠，
   在任何深度都匹配，带前导下划线的文件在本目录同样进不了库——除非 `git add -f`，而那正是
   判据 B 拦的形状。
2. 文件名要能看出它干过什么（`analyze_failures.py` 可以，`tmp2.py` 不行）。这里的东西没人维护，
   名字是唯一留下的线索。

## 新增一份要做的事

```bash
python scripts/check_oneshot_layout.py --write   # 重生成 docs/仓库卫生清单.md 的自动段
```

不跑这一步，下一次 `bash gates.sh` 会由判据 A 报「自动段与现读不一致」——那是设计，不是噪音：
目录内容变了，登记面必须跟着变，否则这份清单就是会过期的副本。
