## 四、行为说明

### 4.1 Mock ↔ 真后端切换（`src/api/index.ts`）

```typescript
const USE_MOCK = import.meta.env.VITE_USE_MOCK !== 'false'
export const facade = {
  health: () => USE_MOCK ? mockApi.health() : api.health(),
  // 其余 11 个方法同理
}
```

- 默认（无环境变量）走 Mock，**本地运行无需真后端**。
- `VITE_USE_MOCK=false npm run dev` 切换到 `src/api/client.ts`（真后端 fetch）。
- `VITE_API_BASE` 指定后端基址（默认 `http://localhost:8787/api`）。
- Vite 在**构建时**将 `import.meta.env.*` 内联进产物，切换模式必须重新 `npm run build`。

### 4.2 双实现

| 实现 | 位置 | 适用场景 |
|------|------|---------|
| 单文件版 | `index.html` / `standalone.html` | CDN Vue 3，浏览器直接双击打开，零依赖演示 |
| Vite 工程 | `src/` + `package.json` | 开发/构建，走 npm 依赖与 TS 严格模式 |

两版通过同一份契约，字段与路由一致；离线兜底能力由单文件版提供。

## 六、已知风险

### R1：vue-tsc 存在类型声明警告（非阻塞）
- **现象**：Vue 3.5.x 类型声明变更导致 vue-tsc 报若干警告。
- **影响**：tsc --noEmit 零错误通过；vue-tsc 警告不影响构建和运行。
- **规避**：已添加 `src/vue-shim.d.ts` 补丁；Vue 3.5.x 正式版本的警告会在后续版本修复。

### R2：`npm run build` 沙箱内无法执行（非阻塞）
- **现象**：esbuild 子进程 spawn 被拒（EPERM）。
- **影响**：dist/ 由 AF 侧在完整环境构建，沙箱内无法复现构建流程。
- **规避**：接收方在正常环境执行 `npm install && npm run build` 即可；演示场景使用单文件 `index.html`。

### R3：`SimulationView.vue` 死代码（非阻塞）
- **现象**：第 65 行 `<SafetyAlert v-if="false" :diagnostics="[]">` 永假条件，属 t5 遗留。
- **影响**：无功能影响，TS 无报错；仅作代码整洁问题。
- **后续**：可在 Round 2 或后续 PR 中清理。

### R4：`/build` 和 `/conf/{name}/intervene` 端点无页面调用（非阻塞）
- **现象**：这两个端点在 API 层已实现，但当前 Round 1 无对应的 UI 页面调用。
- **影响**：不影响已有功能；为 Round 2 预留扩展点。
- **说明**：已如实记录在契约对照表和交付回执中。

### R5：t11 真后端契约一致性核查尚未完成（待跟进）
- **现象**：reviewer 正在执行 t11（T2.2 真后端契约一致性核查），状态 in_progress。
- **影响**：此核查属于质量门禁，未完成前交付为「有条件 PASS」。
- **后续**：待 t11 完成并输出 verdict 后，如有问题需在交付回执中补充。

### R6：无认证 / 鉴权
- **现象**：Round 1 全部端点公开，无登录、无权限。
- **影响**：适用于内部演示与只读场景；如接入生产需自行添加鉴权层。
- **说明**：这是 Round 1 只读控制台的既定范围，非缺陷。
